## 1. The judgment call: depend vs transcribe

**Decision: transcribe, not depend.** Full reasoning, with the evidence behind it, is written up
in `docs/linux-rewrite/COSMIC-DESIGN.md` §1 — summary here:

- `cosmic-theme`'s own `Cargo.toml` (git checkout, rev `1f8d8786`, at
  `~/.cargo/git/checkouts/libcosmic-*/*/cosmic-theme/Cargo.toml`) hardcodes `cosmic-config`'s
  `subscription` feature **on**, unconditionally. Cargo feature unification means no downstream
  consumer can turn that back off. `subscription` pulls `iced_futures` — a Wayland/iced-only
  dependency chain with nothing else like it anywhere in this GPUI-based workspace.
- This was verified by building, not by reading a changelog: a scratch probe crate depending only
  on `cosmic-theme` from git was compiled end to end, and `cargo tree` was run against it,
  confirming the iced chain. The narrower "depend on `cosmic-config` alone" path was also probed
  and still needs two unpublished git dependencies transitively.
- The "prize" of depending — real accent/light-dark pickup from the user's actual COSMIC
  configuration — was not given up. `crates/sirio_theme/src/cosmic/live.rs` is a
  dependency-free reader of COSMIC's on-disk RON config (`$XDG_CONFIG_HOME/cosmic/<config-id>/v<n>/<field>`,
  XDG-fallback `~/.config`), using a narrow hand-rolled parser for exactly the RON shapes COSMIC
  writes (not a general RON library). `CosmicTheme::resolve` tries this live reader first, falls
  back to the transcribed stock palette when no config is present.
- **Verified against this real machine, executed, not simulated**:
  `cosmic::live::tests::detects_the_live_cosmic_theme_when_present_or_falls_back_cleanly` prints
  `live COSMIC theme detected: is_dark=true accent.base=rgba(0x63d0dfff)` when run — the genuine
  current system accent on this Pop!_OS 24.04 box.
- **No-COSMIC-config case verified too**: when `live::detect()` finds nothing (or a malformed
  config), `resolve()` falls through cleanly to the transcribed defaults — no panic, no
  zeroed/default-initialized struct. Covered by
  `cosmic::theme::tests::system_mode_never_panics_and_always_resolves` and exercised implicitly
  by every other `cosmic::theme`/`cosmic::palette`/`cosmic::semantic` test, none of which run
  inside a real COSMIC session and all of which pass by falling back correctly.

## 2. What the token layer exposes

New module `crates/sirio_theme/src/cosmic/` (10 files, 1280 lines total, all new — see §5 for
the full file list and line counts). Public surface (re-exported from `cosmic::mod`):

- `CosmicContainers` / `CosmicContainer` — the 3-layer hierarchy (`background` → `primary` →
  `secondary`), each with `base`/`on`/`divider` plus a nested `CosmicComponent`.
- `CosmicComponent` — one semantic role's full interaction range: `base`/`hover`/`pressed`/`on`/`divider`/`border`.
- `CosmicSemanticColors` — 13 named roles (`button`, `accent`, `accent_button`, `success`,
  `success_button`, `destructive`, `destructive_button`, `warning`, `warning_button`,
  `icon_button`, `link_button`, `list_button`, `text_button`) + `shade`.
- `CosmicSpacing` — the 10-step scale (`none`=0 … `xxxl`=128).
- `CosmicRadii` — the 6-step corner-radius scale (`radius_0`=0 … `radius_xl`=160).
- `CosmicTheme` — the composed `gpui::Global`, with `get`/`install`/`init`/`set_mode`/`for_mode`/`light`/`dark`,
  mirroring `Theme`'s own API shape so migrating a surface is a search-and-replace of the type
  name, not a new mental model.

`active_hint`, window gaps, and the 14-level frosted-blur alpha map are **explicitly not
delivered** — documented as such (not silently dropped) in `COSMIC-DESIGN.md` §3.5, because
nothing in this codebase draws window-manager-level chrome yet and transcribing untested numbers
nobody reads would just be unverified surface area.

### How the existing `Theme` seam survived

`crates/sirio_theme/src/lib.rs` — **one edit, four lines**, an insertion only:

```diff
 use gpui::{App, FontWeight, Global, Pixels, Rgba, Size, WindowAppearance, px, size};
 use std::collections::HashSet;
+
+/// Pop!_OS COSMIC design tokens — additive, does not touch anything below.
+/// See `docs/linux-rewrite/COSMIC-DESIGN.md`.
+pub mod cosmic;
 use std::ops::Deref;
 use std::sync::OnceLock;
```

Nothing else in this 55KB, 13+-call-site file changed. `CosmicTheme` is a second, independent
`Global` — a surface opts in by calling `CosmicTheme::get(cx)` instead of `Theme::get(cx)`; both
can be (and are, in the reference surface) installed in the same running app at once.
`cosmic::theme::CosmicTheme::resolve` reuses `lib.rs`'s own private `ThemeMode::resolve`/`resolve_system`
methods directly (visible to it via Rust's "private items are visible to descendant modules" rule)
rather than re-implementing "what does System mode mean" a second time, so the two token layers
can never disagree about that.

## 3. The reference surface: `titlebar.rs`

`crates/sirio_ui/src/titlebar.rs` — chosen because it is self-contained (a single ~48px chrome
bar, its own small entity, its own test module) and not owned by any of the other three agents
active in this worktree (pi: `settings.rs`/`sidebar.rs`/`chat.rs`; codex11: `sirio_terminal`;
codex12: `main.rs`/`sirio_control`/`tab_bar.rs`).

What changed, and what deliberately did not:

- **Colors, hierarchy, radius, one spacing step → COSMIC.** Background is
  `cosmic.containers.primary.base`; a new 1px `border_b` in `cosmic.containers.primary.divider`
  marks the primary/background seam (a real COSMIC headerbar pattern); the two icon toggles use
  `cosmic.semantic.icon_button` (`on` resting, `hover` fill); corner rounding is
  `cosmic.radii.radius_xs[0]`; the trailing inset is `cosmic.spacing.xs` (12px), replacing a
  bespoke, untested 14px literal.
- **Geometry stayed waku's, on purpose.** `HEIGHT` (48px), `CONTROL_SIZE` (26px), `CONTROL_GAP`
  (6px), `TRAFFIC_LIGHT_INSET` (14px) are untouched — `crates/sirio_ui/src/conformance.rs`'s
  `bars_and_rows_use_the_measured_density` test asserts these byte-for-byte as waku's measured
  physical scale, a separate, independently-owned contract I have no reason to break. This line
  is drawn explicitly in `COSMIC-DESIGN.md` §6, not left implicit.
- **`Titlebar::new` now self-bootstraps `CosmicTheme`** (`if !cx.has_global::<CosmicTheme>() { CosmicTheme::init(cx); }`),
  so the surface renders correctly whether it's opened through the real app shell
  (`crates/sirio/src/main.rs`, unmodified, still calls `Titlebar::new` exactly as before) or
  standalone (the demo, a test) — without requiring `main.rs` to know about the new token layer
  yet. If a global is already installed (as the new drawn tests do, explicitly, before
  constructing the entity), the bootstrap is a no-op and the pre-installed mode wins.

Files touched for the restyle: `crates/sirio_ui/src/titlebar.rs` (99 insertions / 15 deletions),
`crates/sirio_ui/examples/chrome_demo.rs` (11 insertions / 1 deletion — added a
`SIRIO_COSMIC_MODE=light|dark` env override, installed *before* `Titlebar::new` runs, purely for
deterministic screenshot capture of both appearances; unset, it follows the system portal exactly
like the real app shell).

### Light and dark, both

`CosmicTheme::resolve` is appearance-aware the same way `Theme` is. Proven two ways:

1. **Unit level** (`cosmic::theme` tests, context-free): `dark_mode_resolves_to_the_dark_container_hierarchy`,
   `light_mode_resolves_to_the_light_container_hierarchy`, `light_and_dark_helpers_do_not_require_an_app_context`,
   `system_mode_never_panics_and_always_resolves`.
2. **UI level, on the reference surface itself** (drawn, GPUI `TestAppContext`/`VisualTestContext`):
   `titlebar::tests::titlebar_draws_the_cosmic_primary_container_in_dark_mode` and
   `titlebar::tests::titlebar_draws_the_cosmic_primary_container_in_light_mode` — each installs
   `CosmicTheme` explicitly in one mode *before* the `Titlebar` entity exists, so the assertions
   only pass if `render` genuinely reads the pre-installed global back (not a hardcoded value),
   then confirm via `.debug_bounds("titlebar-sidebar")` / `.debug_bounds("titlebar-right-panel")`
   that both controls are actually drawn at the right size under each appearance.

Appearance-tier (screenshot) evidence for both modes: **not captured this session** — see §6,
"honest remainder." This is the one piece of evidence I could not produce, and why.
