F-TERM-SCR-02 resize-debounce burst count — raw instrument log
================================================================

Setup: `f-term-scr-02-winch-trap.sh` typed into a real Terminal pane's shell
(pane-4 in the live `wf-sweep2` instance's fixture project), then the pane
was split (right-click -> Split Right) to create a real draggable divider.
The trap arms `WINCH`, prints `TRAP_READY`, then sits in a tight
`while true; do sleep 0.02; done` loop so pending SIGWINCH is picked up
within ~20ms of delivery, without needing the shell back at its prompt.

All timestamps are host `date +%s.%3N` (same clock as the WINCH handler's
own `$(date +%s.%3N)`, since both run on the same machine — this is a
nested Wayland session, not a remote host).

--- Result ---
6 real pointer-driven resize opportunities (down + 4 move + up, 346ms span)
collapsed to exactly 1 delivered WINCH, arriving at 1787103068.561 — i.e.
204ms AFTER the drag's own `up` event (1787103068.357), not synchronously
with any of the 6 pointer ops. The log then stayed flat for a further 3.7s
of polling with no further deliveries, so this was not a first-of-many
event either — one settle, one delivery, done. cols jumped straight from
90 to 65 in that single delivery; no intermediate WINCH for any column
count the pointer physically passed through mid-drag.

This is the burst-count evidence the ledger asked for: not "constants
match" by reading source, but an actual instrumented count of raw input
events versus actual resize deliveries to the child process, with the
delivery visibly lagging gesture-end rather than tracking it 1:1.

Bonus corroboration from the SAME log (visible in
`f-term-scr-02-winch-count-burst.png`): two EARLIER WINCH lines
(1787102928.020 cols=89, then 1787102928.241 cols=90, 221ms apart) came
from a single quickshot()'s own resize-down/resize-up dance (1715x972 ->
1714x972 -> 1715x972) — a real two-step window resize outside any
deliberate drag — and that also produced exactly one WINCH per direction
change, not a flood, consistent with the same debounce/settle path.
