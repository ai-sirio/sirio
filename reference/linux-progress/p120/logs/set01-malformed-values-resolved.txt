F-CORE-SET-01 -- malformed settings values written directly to the DB, then app restart
instrument: database (/tmp/p120a.sqlite `setting` table) + process restart

Malformed rows inserted directly via python3's sqlite3 module (bypassing the app entirely):
  appearance.uiFontSize       = "not-a-number"
  appearance.terminalFontSize = "99999"
  appearance.theme            = "totally-bogus-theme"
  controlSocket.enabled       = "maybe-ish"
  usage.refreshIntervalMin    = "-500"
  general.summarizerAgent     = "not-a-real-agent"

Insert script (setting table schema: `CREATE TABLE setting (key TEXT PRIMARY KEY, value TEXT NOT NULL)`):
  rows = [
      ("appearance.uiFontSize", "not-a-number"),
      ("appearance.terminalFontSize", "99999"),
      ("appearance.theme", "totally-bogus-theme"),
      ("controlSocket.enabled", "maybe-ish"),
      ("usage.refreshIntervalMin", "-500"),
      ("general.summarizerAgent", "not-a-real-agent"),
  ]

App process (original pid 3053396) killed, a fresh process relaunched against the same on-disk DB
and the same already-running sway compositor:
  kill <old_pid>
  env -u DISPLAY TILLER_SOCKET=/tmp/p120a.sock TILLER_DB=/tmp/p120a.sqlite \
      WAYLAND_DISPLAY=<wd> XDG_RUNTIME_DIR=<dir> SWAYSOCK=<sock> \
      rust/target/debug/tiller >>/tmp/p120a.log 2>&1 &

No crash. /tmp/p120a.log after restart shows only pre-existing Mesa/EGL/Vulkan/radv warnings
(libEGL driver-name lookup failures, "MESA: error: ZINK: failed to choose pdev", "radv is not a
conformant Vulkan implementation, testing use only") -- all present before this restart too, not
new, no panic/backtrace lines.

Resolved values read back via `ctl surface.settings.read` after restart:
  interfaceFontSize    -> "13"     (unparseable string "not-a-number" -> fell back to Swift default)
  terminalFontSize     -> "24"     ("99999" -> clamped to range max)
  theme                -> "system" (bogus enum string -> fell back to default)
  controlSocketEnabled -> "true"   (unparseable bool "maybe-ish" -> fell back to default; the
                                     socket itself stayed live and responsive throughout -- further
                                     control calls succeeded after this restart, including the
                                     surface.settings.read call that produced this very evidence)
  refreshInterval      -> "1"      ("-500" -> clamped to range min 1)

summarizerAgent: not independently re-read via `ctl` this pass -- reasoning is from a direct code
read of tiller_persistence/src/db.rs's settings() (allow-list only accepts
"claude"|"codex"|"opencode"|"pi"|"omp", anything else silently ignored/defaulted), not from a live
observation. Flagging this distinction rather than presenting it as equally strong evidence to the
five rows above, which were all read back live post-restart.
