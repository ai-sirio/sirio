(`/dev/shm/tt/debug/tiller`) via `Scripts/wayland-drive.sh`, label `fset11main` for the main
multi-invocation lane (fixture `/dev/shm/fset11-fixture`), plus two dedicated negative-control

short-lived recon lanes (`fset11recon*`) used only to locate on-screen coordinates before spending

deliverable is this report; every frame cited below was actually opened and read, not assumed).

**The `Scripts/wayland-drive.sh` `scroll` action is dead on this build.** Verified with a positive
control before blaming anything downstream: opened a terminal, ran `seq 1 200` (200 lines, only
the last ~20 visible), then sent `scroll <x> <y> 200` — the frame before and after are byte-for-byte
different only in a moved cursor icon; scrollback never moved. Reused the same probe against the
Settings→General page (steps -30 through 200, multiple x/y) with the same null result. This is a
harness limitation, not a Settings defect, and it is not scoped to Settings. Worked around for every
row that needed content below the fold by resizing the nested output taller with the compositor's
own `swaymsg … output HEADLESS-1 resolution WxH` primitive (the same mechanism `shot()` already uses
internally for its repaint-forcing nudge) and capturing with a raw `grim` call, updating `OUTPUT_W`/
`OUTPUT_H` so subsequent clicks stayed correctly scaled. Recorded here so the next critic doesn't
waste a pass rediscovering it, and doesn't misattribute it to the app.

## Notable findings that are not row defects but are worth carrying forward

1. **`scroll` is dead in `wayland-drive.sh` on this build** — verified with a positive control (a real terminal with 200 lines of scrollback) before concluding it, per the harness-vs-defect distinction the brief asks for. Worked around throughout this pass by resizing the compositor's virtual output taller (`swaymsg -s "$SWAYSOCK" output HEADLESS-1 resolution WxH`, the same primitive `shot()` uses internally) and capturing with raw `grim`, remembering to update `OUTPUT_W`/`OUTPUT_H` so subsequent clicks stay correctly scaled, and to resize back to `1715x972` before calling the script's own `shot()` again.
2. **`~/.local/share/tiller/credentials.json` is real-host, not per-instance.** Any critic exercising F-SET-12/13 is writing into the *operator's actual home directory*, not an isolated fixture, because the app inherits `$HOME`/`$XDG_DATA_HOME` unmodified from the launching shell and this file's path is never overridden the way `TILLER_DB`/`TILLER_SOCKET` are. Clean up after yourself (`printf '{}' > ~/.local/share/tiller/credentials.json` restores the pristine empty state this pass found and left it in); a concurrent critic doing the same test at the same time can also race you on this file.
3. **`wtype -k ctrl+a` is invalid** — errors `Unknown key 'ctrl+a'`. Use the script's dedicated `chord ctrl a` action for modifier combinations; `key` only takes a single named key.
4. **Escape closes the whole Settings surface even from inside an open leaf popup** (observed while dismissing the Summarizer-agent dropdown: a bare `key Escape` closed Settings entirely and returned to the workspace, not just the dropdown). This does not contradict any row's letter — F-SET-02 only promises Escape returns to the workspace, which it does — but it cost this pass a throwaway invocation when three queued General-page interactions silently landed on the empty workspace behind it instead. Recording it so the next critic doesn't lose the same actions to it.
5. **The AI Providers "Refresh interval" stepper is one shared value across all four providers**, not per-provider (`usage.refreshIntervalMin`, a single DB key) — consistent with every row's live-observed 5→7 min change appearing simultaneously on Claude/Codex/OpenCode/Ollama. Not a defect against any row's text, which never claims independence, but worth knowing before reading four identical numbers as a rendering bug.

My PATH-stripped wrapper (built for F-SET-17) removes *all* binaries, which produces the registry-error banner, not the per-agent Install-button state this row needs. A more surgical wrapper (a `PATH` containing everything except, say, `opencode`) would close this — not built this pass.

Selection and DB persistence are solidly proven; I did not additionally open a Claude Code pane and confirm its accent visually updated.
