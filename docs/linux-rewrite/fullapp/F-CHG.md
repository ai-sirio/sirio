## Defects found this pass

1. **F-CHG-06 — Files-tree status dot cannot show "staged".** `DirectoryGitStatus` (the type behind the per-row marker) has only `Conflicted`/`Changed`/`Untracked` — no `Staged` variant — so a 100%-staged file (rename or new-file-add, zero unstaged component) renders the *same* amber dot as a genuinely unstaged-modified file. Pixel-verified live: `file.txt` (Changed), `image.bin` (Changed), `README2.md` (staged rename), `staged.txt` (staged add) all sample to identical `#F2B847`. The Changes-list panel (a separate view) gets this right (green/amber/blue distinct). Repro: any worktree with one staged-only file and one unstaged-modified file, open Files panel, sample the marker dot colour for each — they match when the Swift original (and the row's own clause) says they should not.
2. **F-CHG-15 — a single unreadable tracked file takes down the whole Changes tab, not just its own row.** `chmod 000` one already-tracked, already-modified file (leave everything else alone, `.git` fully readable) and the Changes tab renders `"Git is unavailable: … cannot hash <file>"` for the **entire worktree**, hiding every other file's real diff, instead of showing the other files normally with a "diff unavailable" message on just the broken one. Root cause: `tiller_git::diff::stats()` runs one whole-repo `git diff --numstat HEAD` and treats any non-zero exit as total failure. Repro: `git init`, commit a file, modify it and `chmod 000` it, modify a *second* tracked file normally, open Changes — both files disappear behind the whole-repo error, not just the broken one.
