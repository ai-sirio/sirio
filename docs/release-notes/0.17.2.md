One fix to the file editor, to a message that took the file away.

**A message about your file is no longer shown instead of it**

Asking where something is defined, and getting no answer, replaced the
whole editor with the sentence "No definition found" — and left it
there. Nothing in the app ever took it back down, so the file stayed
gone until you closed the tab and opened it again.

Four other messages went the same way, for the same reason: a language
table that would not parse, a language server that would not start, an
error answering a definition, and a failed save. The last is the worst
of them, because it removed from the screen exactly the text you were
trying to rescue.

All five now appear on a small card over the file, which stays where it
is and stays readable. A click dismisses the card.

**And the answer appears where you asked the question**

An answer about a definition is shown next to the place you asked —
where you right-clicked, or where you held the platform key and clicked
— rather than in the middle of the window. Messages that nothing
pointed at, like a failed save, settle into the corner of the view
instead of borrowing a position from somewhere you are no longer
looking.

When a definition *is* found, its file opens in its own tab, and an
already-open file is brought forward rather than opened twice. That part
already worked; it had simply never been covered by a test, and now it
is. It looked broken in 0.17.0 because every request failed before it
could get that far — that was 0.17.1's fix.
