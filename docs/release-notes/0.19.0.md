The last release taught Sirio the name of every language's server, and then
said: install the one you want and reopen the file. This one does the
installing.

**Sirio can fetch fifteen of the twenty-one**

Open a Markdown file on a machine with no `marksman`, or a TypeScript file
with no `typescript-language-server`, and a card offers to go and get it.
One click fetches the server and starts it — the actions appear without
reopening anything. Servers that ship as a download are checked against a
hash compiled into the app before they are unpacked; the ones that come
from npm are installed at a version pinned the same way. It is the same
installer and the same store that already handled coding agents; language
servers simply moved in beside them.

The offer is made once per language, not once per file, and a "Don't ask
again" makes it stop for good. A language you declined is not asked about
on the next file, or after a restart.

**The six it cannot fetch say why**

`jdtls` needs a JVM (Java 21 or newer) and `kotlin-language-server` a JVM
17 or newer; `gopls` needs Go, `ruby-lsp` needs Ruby, and `sourcekit-lsp`
arrives with a Swift toolchain rather than on its own. Sirio will not offer
a button it cannot honour, so each of those names the thing that has to
come first and links to its instructions instead. An offer that would fail
is worse than no offer.

Zig's `zls` is the one that is our fault rather than yours: it publishes
only `.tar.xz` archives, and Sirio cannot unpack that format yet. It is
listed with the same honesty as the rest — what is missing, and where to
get it — until that changes.

**Your own `PATH` still wins**

If you already have a server installed, that is the one that runs. Sirio
looks at your `PATH` first and only then at what it fetched itself, so
installing through the app can never displace a version you chose on
purpose. Entries in `~/.config/sirio/languages.toml` are still read before
the built-in table, and a server you named there is never second-guessed —
Sirio offers no copy of something you already decided about.

**Settings → Language Servers**

All twenty-one in one list, each saying whether it is on your `PATH`,
installed by Sirio, or absent, with its action next to it. It is also
where a declined offer comes back: turn the offer on again for a language
you said no to earlier.

**The right-click menu explains itself**

"Go to Definition" and "Find References" used to go grey on a file whose
server was missing. They stay clickable now and offer to install, because
a disabled row with a reason is a dead end and a live one is a way out.

---

This release exists because of a bug report about Java: every token
answered `No language server offers references here`. Nothing was wrong
with the navigation — `jdtls` was not installed, and nothing said so. The
two cases look identical from inside the app, which is why 0.18.0 could
ship without noticing. They do not look identical any more.
