Sirio has recognised twenty-three languages since the file editor arrived.
Eight of them were coloured, and four could answer a question. This release
makes it all twenty-three, in both senses.

**Every language you can open is coloured**

Java, C, C++, Swift, Kotlin, Ruby, PHP, Lua, Zig, YAML, HTML, CSS, SQL,
XML and Markdown join Rust, Python, TypeScript, JavaScript, Go, JSON, TOML
and shell scripts. Nothing to install and nothing to turn on: the grammars
are part of the app, and a file is coloured the moment it opens.

This is what was wrong with Java. The editor knew the file was Java — it
said so in the status line — and then drew it as if it were a text file,
because there was no grammar behind the name. There was no message about
it, and there could not have been: a language with nothing to colour and a
language with no colours available look exactly alike from the inside.

Comments in Swift, SQL and Zig deserve a mention of their own. Those three
grammars ask for two things at once on a comment, and the second one wins
— so shipping them as written would have painted every comment in those
languages the same colour as ordinary text. They are the reason this was
worth testing rather than trusting.

Python stub files (`.pyi`) and JSON-with-comments (`.jsonc`) are coloured
too; `.pyi` in particular had been able to reach a language server for
months while still being drawn as plain text.

**And every language can have a language server**

"Go to Definition", "Find References", the outline and the error markers
need a language server — a separate program, on your `PATH`, that
understands the project. Sirio now knows which one each language uses:
`clangd` for C and C++, `jdtls` for Java, `sourcekit-lsp` for Swift,
`ruby-lsp`, `intelephense`, `zls`, `lua-language-server`, `marksman`,
`taplo` and the rest, alongside the `rust-analyzer`, `gopls`, `pyright`
and `typescript-language-server` that were already there.

Knowing the name is not the same as having the program. Install the one
you want and reopen the file; the actions appear. Until then nothing is
said about it — a server you have not installed is not a problem, and a
message on every file you open would bury the one case that is worth
telling you about, a server that *is* installed and failed to start. That
one still says so, and names the command.

Any of these can be replaced in `~/.config/sirio/languages.toml` by adding
an entry for the same file extension. Your entries are read first, so
overriding one takes a few lines and no hunting.
