A pull or merge request's code now opens inside Sirio: its Files tab is the
diff, and a file opens in the editor. Text across the app can be selected and
copied. The terminal has a scrollbar, the sidebar can fold every project at
once, and there is a new base colour that starts at pure black.

**A change request's diff, inside Sirio**

The Files tab of a pull or merge request is now its diff. It lists the changed
files with their additions and deletions. A file's diff is read when you open
its row, in Unified or Split, and the files you opened stay open when the
request gets a new head.

When the request's commits are not in your repository yet, Sirio fetches them
by itself. It runs one non-interactive `git fetch` with git's own credentials,
a credential helper or an ssh key, never the token Sirio holds for the forge.
It never prompts, gives up after two minutes, and touches none of your
branches or tags. What it fetched is kept under `refs/sirio/change-requests/`,
only so that git does not collect it, and is removed once no tab needs it. If
the fetch cannot sign in, the tab says that it uses git's credentials and not
the token.

Open in editor opens the file in your worktree when the worktree is at the
request's head. Otherwise it opens a read-only snapshot of the file at that
revision, in a tab of its own; for a file the request deletes, the snapshot is
of the base. Snapshots come back after a restart. In Commits, a click fetches
the commit if it is missing and then opens it in Changes. A line comment's
`path:line` switches to Files and opens the diff there.

Sirio still only reads. The diff's heading still says Staged (N), which it
inherits from the Changes view.

**Select and copy text**

Text in Settings, change requests, dialogs, banners and the diff could be read
but not copied. It can now be selected. Drag to select, double-click for one
segment of a path or a branch (`/` and `\` separate it, `-`, `.` and `_` do
not), triple-click for the whole line, and Ctrl+C, or Cmd+C on macOS, copies.
There is one selection at a time.

It covers Settings, the change request tab and list, the status bar, dialogs,
banners and notices, Markdown shown outside the chat (the file Preview, a
request's description and comments), a tool call's output in the chat, and the
code of a diff in both views. Ctrl+C is not taken from anything else: in a
terminal it still interrupts, and the file editor keeps its own Copy.

Some text stays unselectable: anything inside something you click, such as the
sidebar's rows, tabs, the command palette and the file, history and commit
rows, and also the title bar, the question dock and the chat's permission and
plan cards. A drag stays within one run of text, and does not carry on into
the next label. Pasting a selection with the middle button on Linux does not
work yet.

**A scrollbar in the terminal**

The terminal pane has a scrollbar along its right edge, like the chat and the
file view. Its thumb follows the view through the scrollback, and dragging it
moves the view. It is drawn over the text, so it never changes the number of
columns and the program running is not sent a resize. On the alternate screen
(vim, full-screen programs) there is no history, and it disappears. While it
shows, the narrow strip under it no longer takes clicks, so selecting text and
mouse reports start beside it.

**Onice, a base colour that starts at black**

Settings → Appearance gains a seventh choice in Base color, Onice. It has no
hue, and in dark mode its greys start at pure black: the terminal and the
central panes are #000000, sidebars and panels #0A0A0A, the chat and dialogs
#141414. Depth comes from those steps alone, since a shadow cannot be darker
than black. Light mode is the same as Neutral's. An older Sirio does not know
Onice and falls back to Neutral.

**Fold every project at once**

Two icon buttons beside the + at the top of the sidebar fold and open every
project, and so all its worktrees, in one click. The words are in their
tooltips. They select nothing: the worktree you are in stays the selected one
even when its row is hidden. A typed filter still decides what is drawn. They
appear in the Projects view only.

**Smaller changes**

- **glab 1.119 no longer makes a self-managed GitLab answer "Unexpected end of
  document".** glab sent the query without saying it was JSON, and GitLab read
  no query at all, so the change requests view showed an error instead of the
  list. Sirio now says it. `gh` was not affected.
- **The This worktree card follows the branch.** After a `git switch` it kept
  looking up the branch the panel had connected on, and said "No PR for main"
  while the list below showed the pull request of the branch you were on. It
  now reads the branch each time, and hides itself on a detached HEAD. Create
  on the forge is a + icon; its old label is the tooltip.
- **`sirioctl` can drive the new views.** `surface change-request reveal`,
  `open-file` and `open-commit`, `surface tabs read`, `select` and `close`, and
  `surface file read` open and read a request's files, the right pane's tabs
  and a file's text, so the flow can be scripted.
