A native Claude chat now answers the questions an MCP server asks you, the
chat composer can be dragged taller or shorter, and every text in the window
follows the interface font size. OpenCode 2 tabs get their sessions from
Sirio again, and several chats, menus and rows that kept stale state now
keep up.

**MCP servers that ask you something**

When an MCP server asks for input in a native Claude chat, the question
opens as a card in the chat, where Claude's own questions appear, instead
of leaving the turn hanging.

- A form is asked one field at a time, then shown whole with Accept and
  Decline. Text, numbers, yes/no and lists of choices are supported, and
  required fields are marked.
- A request to visit a link shows the link with Open and Decline. Open
  launches the browser and accepts.
- A question left unanswered for 5 minutes is cancelled, and the card says
  so. A question the server withdraws, or that an interrupt cancels, closes
  its card.
- A request Sirio does not handle is refused with an error, so the turn goes
  on instead of waiting.

**A composer as tall as you want it**

Drag the top edge of a chat's composer to set how many rows the field grows
to before it scrolls. Until now it always grew from 3 to 12 rows.

- One value applies to every chat, open now or opened later, and it
  survives a relaunch.
- The rows follow the interface font size, so a larger font never lets the
  composer take over the chat.

**Text follows the interface font size**

**Settings › Appearance › Interface font size** now sizes every text in the
window: chat messages and the composer, Markdown Preview, change-request
bodies, settings pages, the Trace and CI log rows, tab strips and the
terminal's banners and menus. The terminal grid itself still follows
**Terminal font size**. At the default size of 13 nothing moves.

**OpenCode 2**

OpenCode 2 refuses the plugin Sirio used to install, so its tabs showed no
status and lost their session on relaunch. Sirio now asks OpenCode's
service for a new session and opens the tab on it, so Relaunch and Restart
resume the right conversation. With OpenCode 1.x nothing changes. Under
OpenCode 2 the plugin files Sirio wrote earlier are removed; a file you
wrote yourself is left alone.

- A launch that finishes after you switch to another worktree still lands
  in its own tab, and closing a tab while it launches deletes the session
  Sirio had just created for it.

**Fixes**

- Two Claude tabs in the same worktree now each save their own session, so
  each one resumes its own conversation after a relaunch. Before, both
  reported under the tab set up last.
- A restored agent tab whose pane has to take a new id, for instance
  because a tab in another worktree already holds its old one, now starts a
  fresh session instead of possibly resuming that other tab's conversation.
  A restored OpenCode 2 tab in that case starts plain `opencode`.
- A project you clone or create is now added even when you close its form
  before the clone or the new folder is ready. A clone that fails after the
  form is gone says so in the sidebar.
- After Claude refuses to resume a native chat's old session, the fresh
  session Sirio starts instead is now the one saved, so the next restart
  resumes it. **Retry** resumes that fresh session too, and **New
  conversation** always starts from scratch.
- A token saved while Sirio was still checking a forge host for the first
  time is no longer overwritten by that check's "not connected" answer.
- A row in the Sessions view now shows a new status, title or time as soon
  as it changes, instead of at the next unrelated redraw.
- The file editor's context menu now covers the code beneath it: resting on
  a row no longer opens a hover card over the menu, a click on a row no
  longer moves the caret first, and the wheel no longer scrolls the code.
- A native Claude chat that went silent is now ended cleanly when its time
  runs out, instead of panicking and leaving `claude` running until the
  chat closed.
- **Restart** on a tab whose agent already started, and the restart offered
  by its overlay, no longer send the tab's first prompt again. This holds for
  every agent.
- Text fields draw their caret on whole pixels, an input method's candidate
  box stays next to the text, and a one-line field that loses focus shows
  its start again.
- A strip of tabs too wide for its panel now scrolls and cuts long labels
  instead of overflowing.
