Everything here is repair, and most of it lands on the code editor — a
surface you could read and click but only half type on, because two of its
keyboard routes were declared and then wired to nothing. The Files panel's
new hidden-entries switch loses an icon, and creating a project no longer
depends on its parent directory already being there.

**Copy, Cut and Paste reach the editor from the keyboard**

Ctrl/Cmd-C, -X and -V worked in the chat composer and in the settings fields
and did nothing in a source file; the right-click menu was the only way to
move text in or out. The editor's key handler returned on every command
chord, on the premise that something above it would answer them — nothing
does, because the keymap context it names carries no binding anywhere in the
app. The chords now raise the same action the menu raises, so the two routes
cannot answer one key differently. Select-all answers Cmd-A as well as
Ctrl-A, which is what select-all-then-copy needed on macOS. Under the
Markdown preview the chords stay quiet: a paste there would rewrite the
buffer at a caret the reader cannot see.

**The arrow keys move the caret up and down**

Up, Down, Page Up and Page Down were no-ops in a source file — not a wrong
move, no move at all. They walk the document now, remembering the column you
started in, so descending through a short line and coming back up returns
the caret where it began. Down on the last line stops at that line's end
rather than one byte past it, where nothing would have painted it, and a
vertical move scrolls the line it lands on into view, so Page Down no longer
takes the caret a viewport away from the only place it is drawn.

**The hidden-entries switch is one icon, not two**

0.23.1 put an eye and a crossed-out eye side by side in the Files footer with
whichever was active filled in — a pair you had to read before you could use
it. There is one icon now, and it shows what pressing it will do: an eye
while the dotfiles are hidden, a crossed-out eye while they are shown.

**A project can be created where nothing exists yet**

The create-project form proposes `~/Sirio/projects` as the parent, which on a
fresh install does not exist — and creation failed on the missing directory
instead of making it. Missing ancestors are created now. The project
directory itself is not: creating one that already exists stays a visible
failure rather than a silent adoption of a folder someone else put there.
