In Sirio's chat, a message that starts with `!` now runs as a terminal
command, the way `!` works in Claude Code and Codex. Codex, Pi and Oh-My-Pi
chats also get their effort chip.

**Run a command with `!`**

- Type `!` and a command, for example `!git status`, and press Enter. The
  command runs inside the chat, in the chat's working folder and with the
  agent's environment. It does not go to the agent, and the agent does not
  start a turn. This works with every agent, also while a reply is streaming
  or when the agent is offline, but not while the chat waits for you to
  answer a question.
- While your message starts with `!`, the line between the chat and the
  composer stands out: lighter on a dark theme, darker on a light one. To
  send the agent a message that starts with `!`, put a space in front of it.
- Each command shows as a block with its output, its exit status and how long
  it took. While it runs, the block has a spinner and **Stop**. Several
  commands can run at once.
- Each command runs in a fresh shell (your `$SHELL` on macOS and Linux,
  `cmd.exe` on Windows), with no keyboard and no terminal. The shell does not
  read `.zshrc` or `.bashrc`, so your aliases are not there, and `!cd` and
  `!export` do not carry over to the next command. The output has no colours.
  Programs that need a keyboard, such as `vim`, `htop` or a password prompt,
  are not supported.
- ↑ in the composer recalls a command as you typed it.
- Text that starts with `!` sent through `sirioctl` runs as a command too.

**What the agent sees**

- Finished commands go to the agent with your next message, in front of what
  you type, as Claude Code does with its own `!`. Until then the block reads
  "goes with your next message". One message carries up to 30,000 characters
  of output. When there is more, the newest commands keep theirs first, and
  a command left with no room is sent with its status only.
- There is no way yet to keep a block from being sent, so think twice before
  running `!cat .env` or anything else that prints a secret.
- A slash command such as `/compact` is sent without the blocks, which wait
  for your next message.

**Long output**

- A block shows the last 40 lines. Its button opens the rest: **Show all**,
  or **Show last N lines** when there is more than the 2,000 lines and
  64 KiB the block can show, with a note saying how many earlier lines are
  left out. A very long line shows its first 2,000 characters and counts the
  rest.
- At most 1 MiB of output is kept per command. The agent gets what was kept,
  within the 30,000-character limit, not only what the block shows.

**Stopping a command**

- **Stop** ends a command. On macOS and Linux it asks first, and ends the
  command 2 seconds later if it is still running; on Windows it ends it at
  once. Escape in the composer does the same to every running command of the
  chat, a second Escape ends them at once, and only then does Escape stop the
  agent's turn.
- Programs a command leaves running, such as `!make &` or an app it opens,
  end with the command.
- Closing the tab, quitting Sirio, starting a new conversation or opening a
  chat from the history ends every command still running, at once and with
  no chance to clean up, so a `.git/index.lock` or a half-written file can be
  left behind.

**Saved with the chat**

- Finished blocks are saved with the chat. A block that was already sent to
  the agent comes back with its last 40 lines.
- Many large blocks in a row can push the oldest messages out of the saved
  chat.

**Effort for Codex, Pi and Oh-My-Pi**

- Codex, Pi and Oh-My-Pi chats now show the effort chip, which was missing.
  They start on the level their agent reports; Claude and OpenCode still
  start on High.
- Pi chats show the chip alone, without a second pill for the same setting.
- Level names read the way Codex names them: "Medium", not "Thinking: medium".

**Downloads**

Each release now lists every installer twice. The copy with `-update` in its
name is the one in-app updates download, so updates and new installs are
counted apart. Both hold the same bytes.
