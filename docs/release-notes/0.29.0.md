A pull or merge request can now be acted on from its tab: comment, approve or
request changes, close or reopen it, mark it a draft or ready, and edit its
title, description and target branch. Sirio was read-only there until now. The
sidebar also stops opening the projects you folded.

**Act on a change request**

The detail tab of a pull request on GitHub or a merge request on GitLab has
controls now.

- **Comment, Approve and Request changes** are three buttons under the
  Conversation. Ctrl+Enter, or Cmd+Enter on macOS, sends a comment. A comment
  and a request for changes need text, an approval does not.
- **Close or Reopen** and **Ready for review or Convert to draft** are in the
  header, one button for the state the request is in.
- **Edit** opens a card at the top of the Conversation for the title, the
  description and the target branch, with Save and Cancel. Your own comments
  can be edited in place the same way.

A button is there only when the forge says you may press it. Nothing is
offered on a guess: when the forge does not report what the viewer can do, the
control stays hidden, except commenting, which stays unless the conversation is
locked. Nothing is sent that the forge would refuse: approving your own pull
request is not offered, and Request changes on GitLab appears only on a server
that has that state.

Sirio does not paint the result itself. After a write it reads the request
again and draws what the forge says. One write is in flight per tab, and a
write is never retried on its own, because a comment posted twice is worse than
one not posted. When the connection drops after the request left, the tab says
"Could not confirm that it went through. Look at the conversation before
sending it again.", and the words you typed stay in the box. They are cleared
only when the forge accepted them.

**Does my token write?**

Settings → Git Hosting now says, next to a saved token, `can read and write`,
`read-only`, or `scopes not reported`, read from the forge's own answer about
the token. When a write is refused for a missing scope, the message names the
scope to add. A host that goes through `gh` or `glab` says nothing about
scopes: the CLI owns that login.

**What is not here yet**

Merging, choosing reviewers and labels, re-running CI and reading its logs,
inline review threads, and deleting a comment. They come in later releases; the
tab still opens the request in the browser for them.

**Smaller changes**

- **Folded projects stay folded.** With every project folded, opening one and
  clicking a worktree in it opened all the others. Clicking a worktree makes
  Sirio rescan the project in the background, and the sidebar was redrawn from
  the result with every project open. The same redraw ran when the window got
  focus and when a project was added, reordered or had its settings saved, so
  those reopened folded projects too. The fold now follows the project, not its
  row, so it survives a reorder, and a project the sidebar has not shown before
  still starts open. Like the buttons that fold everything, it is still not
  remembered across a restart.
