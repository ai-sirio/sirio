This release changes how a Claude chat actually runs, changes where Project
Settings lives, and closes off the one place a new chat had no starting
point at all.

**Claude Code drives itself now, when it can**

A Claude chat used to always go through the same ACP wrapper every other
agent uses. When the `claude` on your `PATH` is new enough for the protocol
this build speaks, Sirio now launches it directly instead — no wrapper in
between. There is no setting for this: Sirio checks the binary's own
version and decides. Too old, missing, or unreadable, and the chat opens on
the wrapper exactly as before; Settings → Agents names the reason in a
sentence rather than leaving it to guess.

Driving the real process directly is what makes several things possible
that the wrapper alone could not surface honestly: permissions, questions
and plan approvals now come from Claude itself, not from a layer
translating them; the context meter reads from the agent's own accounting
instead of an estimate; and a chat can ask the agent to restore files to an
earlier turn, or resume the exact session a restored chat recorded, because
the native protocol carries what the wrapper's did not.

One bug this surfaced and fixed before it shipped: a turn's end was held
back briefly so the context meter could reach the screen first, and released
on most ways a session could end — but not the one where Claude itself ends
its process to answer an interrupt. On an idle machine that looked like a
chat tab streaming forever, sixty seconds of silence with nothing to show
for it. It is released on every exit now, not just the ones that were
tested.

**Project Settings is a tab, not a sheet**

It used to slide in as an overlay from the sidebar. It now opens as a
Secondary-pane tab titled "Project Settings · {name}" — one per project,
reused rather than duplicated. Edits still save live to the project
catalog; the tab itself is ephemeral, the way any other utility tab is.

**A blank worktree finally offers a chat, not just a terminal**

A worktree with no tabs open showed New Terminal and nothing else. It now
reads "No Terminals or Chats" and sits New Chat right beside it — click it
and the same agent picker the tab bar's own New Chat menu shows expands in
place (Claude Code, Codex, OpenCode, Pi, Oh-My-Pi, or a link to add more).
Pick one and its chat tab replaces the empty state directly.

---

Most of this release is one feature built in stages — the handshake, the
protocol parsing, the turn and permission plumbing, the transport fallback
— landing as one adapter behind a single launch decision, so a Claude chat
is either fully native or fully the wrapper, never a mix of the two.
