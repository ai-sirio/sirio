The file editor can now talk to the language server your project already
has. Open a `.rs` file and rust-analyzer starts in the background; from
then on the editor answers the questions a reader asks — what is this,
where is it defined, where else is it used, what is in this file — and
shows you what the compiler is unhappy about.

**What a symbol is, and where it lives**

Rest the pointer on a symbol and a card appears with its type and
documentation. It waits until the pointer has actually stopped, so
moving across a line does not fill the screen with cards you did not
ask for.

Cmd-click (Ctrl-click on Linux and Windows) jumps to where a symbol is
defined, and "Go to Definition" in the right-click menu does the same.
The jump opens the file if it is not already a tab, and scrolls to the
line even while that tab is still loading. When there is no definition
to jump to, the editor says so instead of doing nothing.

**Errors and warnings where the lines are**

Findings from the language server are marked in the gutter, beside the
line number rather than in place of it — the numbers do not shift when a
file has errors. Errors are red, warnings amber, hints faint. Resting on
a marked line shows the messages in the same card as the hover text, and
that half of the card is built locally, so errors appear immediately and
still appear on a server that offers no hover at all.

**Where else a symbol is used**

"Find References" in the right-click menu opens a new panel on the
right, listing every use grouped by file, each row showing the line and
its source. Clicking a row opens that file at that line. The panel opens
the moment you ask rather than when the answer arrives, so the entry
never looks like it did nothing — and it says which of the four things
is happening: searching, these are the results, nothing found, or the
server is not ready.

**What is in this file**

"Go to Symbol in File" in the command palette opens a list of the
file's functions, types and fields, nested as they are in the source.
Type to filter, Enter to jump, Escape to dismiss. The filter works the
same way the command palette's own does.

**Which servers, and where to say so**

Four languages work out of the box: Rust (`rust-analyzer`), TypeScript
and JavaScript (`typescript-language-server`), Python
(`pyright-langserver`) and Go (`gopls`). Sirio does not install them —
it runs what is on your PATH, and tells you the command it could not
find rather than failing quietly.

Anything else is a few lines in `~/.config/sirio/languages.toml`, which
is Sirio's first user config file. It is re-read when it changes, so a
new entry takes effect on the next file you open, and a file with a
syntax error leaves the previous table in place and says what is wrong
instead of losing your settings.

A server starts the first time you open a file that wants one, and lives
until Sirio quits, so navigation stays instant after the first index. A
server that crashes is not restarted in a loop: one that crashes on a
file will crash again on restart, and on a large project that means
re-indexing forever.

**Menu entries that tell the truth**

Every entry this adds is present with its reason when it cannot run —
"No language server offers references here" — rather than greyed out
with no explanation or, worse, enabled and inert. An entry is enabled
only when a server covering *that file's language* is running and has
said it offers that capability.
