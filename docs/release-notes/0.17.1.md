Three fixes to the file editor 0.17.0 shipped.

**Go to Definition works on the second file you open, not just the first**

Opening a file told its language server the file was empty. The buffer
is read in the background, and the tab asked its server about the file
before that read had landed — so the server was handed `""` and kept it,
because nothing ever sent it a correction afterwards. Every question
asked against that file then failed on a position the server believed
was past the end of a zero-length document:

```
language server returned error -32603: Invalid offset
LineCol { line: 36, col: 28 } (line index length: 0)
```

It looked intermittent because it was: the first file you open in a
project waits for its server to start, and that wait is usually longer
than the file read, so that one worked. Every file after it went to an
already-running server and did not wait for anything.

A file now tells its server what is in it the moment there is anything
to tell, and an edit reaches the server too — which it did not before,
so hover and definition on an edited file described text that was no
longer there.

**Code reads like code**

Syntax highlighting was parsing every file properly and then throwing
most of the answer away: of the twenty-four kinds of token the parser
distinguishes, three survived to the screen. Types, functions, macros,
properties, operators and punctuation were painted as plain text, and a
number came out in the same colour as a string, because both had been
filed under "literal" on the way.

Every kind the parser finds is now painted, with the token colours Zed
uses: keywords purple, strings green, numbers orange, types yellow,
functions blue, punctuation dimmed so a dense line does not read as
noise. Plain identifiers stay your theme's text colour, so the palette
still follows the theme and the appearance you chose.

**Menus you can read**

The editor's right-click menu, its hover card and the terminal's
right-click menu were painted on a surface that goes translucent along
with the panels when the window is blurred — at 70% opacity, with the
desktop showing through the entries. A menu is something an interaction
puts up to be read, so all three now stay opaque over a blurred shell,
the way dialogs and toasts already did.
