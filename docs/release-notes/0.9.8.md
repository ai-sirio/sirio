A fix release. **If you installed 0.9.6 on Windows or Linux, please reinstall
from here** — on many machines 0.9.6 cannot start at all, and it cannot update
itself out of that state.

**Sirio 0.9.6 would not start on CPUs without AVX-512**

Sirio's terminal emulation is compiled by Zig, and the build was targeting the
CPU of the machine that built it instead of a portable floor. The release
runners have Intel Xeons with AVX-512; a great many desktop processors do not —
every AMD Zen 3 part and every Intel consumer chip since Alder Lake, among
others. On those machines 0.9.6 exited the moment you launched it: no window,
no error, no log. Nothing to see, which is what made it easy to mistake for
the app simply not opening.

The Windows installer is where this surfaced. The Linux AppImage was built the
same way and carried the same exposure. macOS was built the same way too, but
the narrow spread of features across Apple Silicon meant it did not misfire in
practice.

Every artifact is now compiled against a portable baseline, and the release
workflow states that floor explicitly rather than inheriting whatever the
build machine happened to offer.

**Why you may have to reinstall by hand**

The auto-updater cannot repair this one. A binary that cannot start never runs
the code that checks for a new version, so there is no path from a broken
0.9.6 to this release except a manual install:

```
curl -fsSL https://dl.sirioai.app/install.sh | sh
```

On Windows, `powershell -ExecutionPolicy ByPass -c "irm
https://dl.sirioai.app/install.ps1 | iex"`, or run the installer below over
the top of the existing one. Your settings, projects and sessions are kept.

If 0.9.6 already runs for you, this release changes nothing you can see, and
the update can wait for its normal prompt.
