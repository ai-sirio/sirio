Two things change what you see. The Files tree and the editor tabs draw
every file and folder with its own icon, and the centre shows both of its
panes from the moment a window opens. Each pane now offers what it can hold
when it is empty. A restart also brings back far more of what you had open:
editor tabs above all, which were saved and then quietly dropped.

**Every file and folder has its icon**

The Files tree used to know about fifty file types and drew a generic sheet
for the rest; folders were all the same folder. It now carries the complete
Material icon theme, 1112 icons for files and folders alike. A folder is
recognised by its name, so `src`, `tests`, `docs` or `.github` look like
what they hold, and it opens into its own expanded icon. Unknown files and
folders still fall back to the plain ones. In a light appearance the few
icons that ship a light variant switch to it, so they stay readable. The
editor's tab glyph follows the same table.

One upstream defect is repaired on the way in rather than inherited. The
theme renames six of its icons without updating the entries that point at
them, which leaves `.gitignore`, `.gitattributes` and `.gitmodules`, among
39 names, pointing at nothing. Here they get the icons they were meant to
have.

**Both centre panes are there from the start**

The right-hand pane, where the browser, the editor, Changes and a project's
settings open, used to appear only once one of them did. It is drawn from
the first frame now, beside the terminals and chats. Ctrl+Shift+B hides it,
and each worktree remembers whether you did. Sirio already meant to
remember this per worktree, but the next save of the layout rewrote the
choice, so a restart could undo it; now it holds. When you hide the pane
while working in it, the active tab moves to the left pane, so Ctrl+W
closes the tab you can see.

**An empty pane offers what it can hold**

A pane with no tabs shows a row of large buttons instead of a blank
surface. On the left they are Terminal and Chat, and Chat opens the agent
picker. On the right they are Browser, Changes, Open File and Project
Settings. Changes is greyed out when the worktree is not a git repository,
and says so when you point at it. Each button shows its keyboard shortcut
where it has one.

**No worktree selected: pick one from the centre**

With no worktree selected, the left pane now says *Select a worktree* and
offers a searchable list of every worktree of every project, as
`project / branch`. Choosing one does exactly what a click in the sidebar
does. With no project at all it says *No projects yet* and offers Add
Project, which is the sidebar's own flow, including its question when the
folder is not a git repository.

**A restart brings back what you had open**

- **Editor tabs come back.** Sirio saved an open file's tab and then skipped
  it on the next launch, as a kind it did not know how to restore.
- **A Changes tab comes back where you left it:** on the commit it was
  showing, and on the file you last opened in it, rather than as the
  generic working-tree view.
- **Each pane comes back on the tab it was showing.** Before, the pane
  without focus fell back to its first tab.
- **Project Settings tabs come back**, in their place in the tab strip.
  A project that has since been removed drops its tab silently.
