# Auto-naming summarizer agent selection

Date: 2026-07-24
Status: approved

## Goal

The user picks in Settings which built-in agent CLI generates auto-naming tab
titles. Every rename uses that agent as primary; if its summarize attempt
fails, Tiller falls back to the tab's own agent (when it is one of the 5
catalog adapters). This also unlocks auto-rename for chat tabs of registry
agents outside the catalog (gemini, goose, …), which today are silently
skipped by the `AgentCatalog` gate in `requestAutoRename`.

## Background

- `AutoNamer.summarize(transcript:worktreePath:adapter:)` runs
  `adapter.summarizerCommand(prompt:)` as a detached process; any failure
  (missing binary, timeout, empty output) returns `nil` silently.
- All 5 catalog adapters (claude, codex, opencode, pi, omp) implement
  `summarizerCommand`.
- Chat panes register canonical registry ids (`claude-acp`, …);
  `AgentIdMigration.catalogId(_:)` maps them back to catalog short ids
  (fix ac0babf).
- Today `requestAutoRename` (App/AppModel.swift) requires the tab agent to
  resolve in `AgentCatalog` — registry-only agents never rename.

## Design

### 1. Setting — `AppSettings` (TillerCore)

- New key: `autoNaming.summarizerAgentId`, stored value = catalog short id.
- Pure resolver beside `autoNamingEnabled`:
  `summarizerAgentId(defaultsValue: String?) -> String`, default `"claude"`;
  unknown/empty stored values also resolve to `"claude"`.

### 2. UI — `GeneralSettingsView` (App)

- Picker labeled "Summarizer agent" directly under the Auto-naming toggle.
- Options: the 5 `AgentCatalog.all` adapters, showing `displayName`.
- Bound with `@AppStorage(AppSettings.summarizerAgentIdKey)`, default
  `"claude"`.
- Disabled when the Auto-naming toggle is off.
- All strings in English.

### 3. Selection logic — `SummarizerSelection` (App/AutoNaming)

Pure helper, fully testable without spawning processes:

```swift
enum SummarizerSelection {
    /// Ordered candidate adapters: the user-selected primary first, then
    /// the tab's own agent as fallback. Deduplicated; fallback only when
    /// the tab agent (via AgentIdMigration.catalogId) is in the catalog.
    static func adapters(selectedId: String, tabAgentId: String) -> [any AgentAdapter]
}
```

- `selectedId` unknown → resolves as `"claude"` (defensive, mirrors the
  resolver default).
- `tabAgentId` gets `AgentIdMigration.catalogId(_:)` applied before lookup.
- Same adapter twice → single entry.

### 4. Rename flow — `requestAutoRename` (AppModel)

- The gate drops the requirement that the tab agent resolve in
  `AgentCatalog`. It still requires: transition `running → done/needsInput`,
  auto-naming enabled, tab found, `titleIsAutoNamed`, and a registered
  `paneAgents[paneId]` (any id, registry or catalog).
- Transcript source selection is unchanged: chat → `ChatTranscriptSource`
  (works for every registry agent), terminal →
  `resolveFileTranscriptSource` keyed on the catalog id (claude/codex only).
- Title generation: iterate `SummarizerSelection.adapters(...)` in order,
  call `AutoNamer.summarize` per adapter, first non-nil title wins. All-nil
  → no rename (silent, as today).

## Out of scope

- Registry agents as summarize engines (the 5 built-in CLIs remain the only
  engines).
- Terminal-tab rename for opencode/pi/omp (no file transcript source).
- Any change to throttle, transition triggers, or notification behavior.

## Verification

- Unit tests: `AppSettings.summarizerAgentId` resolver (nil/known/unknown);
  `SummarizerSelection.adapters` (primary order, fallback, dedup, registry
  tab agent, unknown selected id). No tests spawning real CLIs.
- `Scripts/ci.sh` prints `CI OK`.
- Manual smoke: pick Codex as summarizer, run a Claude chat turn → title
  generated by Codex; uninstall scenario (missing binary) falls back to the
  tab agent.
