## What the measurements mean

`sirio_perf` is opt-in through `SIRIO_PERF_TRACE`. It records static span/event
names, timestamps, thread IDs, entity IDs and durations; never application text.
It uses a bounded nonblocking channel and a background buffered writer.
Overflow increments an explicit loss counter. The analyzer rejects samples if
any loss is reported or the trace has not flushed beyond the sample end.
The accepted observations report zero trace loss.

“Present/s” counts `DirectXRenderer::present` invocations, not physical display
delivery. No presentation errors appeared in the fixture's stderr. Render/view/s
counts Render calls; a cached subtree can paint without another Render call.
Known IDs include views mounted earlier and later replaced, so an observed zero
does not establish that the view was mounted throughout the interval.

CPU uses `GetProcessTimes`, divided by actual elapsed time and 12 logical CPUs.
One-core percentages and CPU seconds are retained in JSON; child process and GPU
cost are excluded. Foreground PID is sampled every 100 ms.

Profile percentages are **inclusive span wall time / sample wall time**, not
sampled CPU attribution. Nested and cross-thread spans overlap and can sum above
100%. Uninstrumented work inside GPUI is unresolved. Probe overhead has not yet
been calibrated; these are instrumented baseline observations, not a qualified
uninstrumented baseline. One sample per case is insufficient for significance.

## Redraw graph: measured and unresolved

1. Windows vsync runs ~60/s. Idle `Windows.draw_window` also runs ~60/s,
   but actual Present is ~1/s. `request_frame(require_presentation=false)`
   permits GPUI to decline a draw. **60 invalidations are not 60 rendered frames.**
2. `RightPanel::ensure_tree_refresh` polls at ~1 s; `refresh` reads Git
   status/tree in the background, assigns the result and unconditionally notifies.
   The instrumented `notify.RightPanel.refresh_complete` count is 15 for each
   initial 15 s idle sample, matching 15 root renders/presents. This identifies
   the dominant observed idle trigger, not a proof of zero other triggers.
3. ACP event processing runs ~48/s, including entry remeasurement; markdown
   parsing also runs ~48/s in response streams. Render/present is substantially
   slower. Timers, composer observers, motion leases and frame callbacks are
   not all instrumented; coalescing and event backlog remain unresolved.
4. Existing `TerminalView::render_count`, sidebar row retention and cached
   child-view contracts were used to choose trace points. Runtime spans add
   actual render observations; `ShellPaintProbe` remains a test-only seam.
5. Motion still deliberately uses `pause_when_inactive(false)` for the sidebar
   and chat orb. No three-spinner focused/background result supports changing it.
6. Layout saves are instrumented at SessionStore methods, but not all SQLite
   work, Git tree traversal, terminal PTY wakeups/settle scans or observer causes.

### The dependency edge, not an activity-model transition

The source path in the actual dependency version `bezel-gpui 0.3.8+zed.82aeef`
is:

```text
Workspace.render
  -> sync_entity_evidence -> surface_evidence -> hidden TerminalView.read
  -> tab header construction -> terminal_exit_label -> TerminalView.read
  -> GPUI records accessed entities as window dependencies
hidden TerminalView Context.notify
  -> App.notify -> tracked_entities -> WindowInvalidator.invalidate_view
  -> window dirty -> Workspace.render, while the hidden terminal is not rendered
```

`EntityMap::read` records accesses; `Window::record_entities_accessed` and
`App::record_entities_accessed` update the per-window tracking set.
`App::notify` explicitly filters invalidators through that set, so this is
not merely an old, monotonic stale-reference entry. A root read is enough
to retain the hidden terminal in the current dependency set. The terminal's
content changes often, but the exit/agent evidence the root reads does not.
The current workspace calls `sync_entity_evidence` from every root render;
the conditional model-change gate therefore does not prevent the dependency
from being recorded in the first place.

## Follow-up: native foreground journal and complete software-latency pairs

The optional journal export approved for this follow-up is now implemented.
This is measurement infrastructure, **not a performance fix**. Build it with
`cargo build -p sirio --bin sirio --features perf-native` in `rust/`.
It enables the pinned GPUI `profiler` feature and reuses its existing bounded
foreground journal. Runtime export additionally requires both a working
`SIRIO_PERF_TRACE` and `SIRIO_PERF_NATIVE_TRACE`. The default build contains no
native exporter module. The launcher strips inherited trace paths and only
sets them from explicit arguments.

The exporter preserves publication/completion order, explicit presented/idle
boundaries, pending-frame metadata and discontinuities. It does not sort
events by their start timestamps. A separate thread drains the existing ring
every 100 ms; there is no new foreground timer or observer. Output is
create-new JSONL with sequence numbers and periodic cumulative-loss/coverage
records. Input records contain a static input-kind name, timestamps and the
invalidation flag, **not typed characters or composer text**. Task records
contain their static source locations. Abrupt exit is not a final-flush
guarantee: the analyzer requires a health record beyond the sample end and
rejects gaps, lost events and ambiguous multiple-window input attribution.
