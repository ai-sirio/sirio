# IDE bridge (`sirio_ide`, `sirio::ide_bridge`, the Proposal tab)

Sirio is the IDE that Claude Code's `/ide` connects to, for every Claude in one of its terminals: Claude sees the editor's selection, gets `@file#Lx-y` from "Send selection to agent", reads the language servers' diagnostics, and shows each Edit it proposes as a diff in Sirio instead of in its prompt. The spec is `docs/superpowers/specs/2026-11-15-claude-ide-bridge-design.md`; **its §10 is the record of every call that overrides an earlier section, read it with §4**. The protocol is not a published contract (the nearest description is claudecode.nvim's PROTOCOL.md), so the posture of [Claude chat](claude-chat.md) holds: degrade, do not reject.

**The rule:** nothing answers an `openDiff` without the user. Read "The answers" before you touch the dispatch.

## The server, the lockfile, the switch

- `sirio_ide` is a leaf crate (no GPUI; `sirio_perf` and `sirio_env` are all it may depend on): the listener, the WebSocket handshake with the token check, the MCP JSON-RPC dispatch (`tungstenite`, synchronous, no TLS), the lockfile and the pure owner walk. One acceptor thread and one thread per connection; a connection's loop reads with a short timeout and in between writes what the app queued and expires deadlines, so a blocked `openDiff` never holds another request. `sirio` is its one dependent: `sirio/src/ide_bridge.rs` owns what the app decides (the switch, the port, the connections, selection coalescing) and `ide_bridge/proposals.rs` and `ide_bridge/diagnostics.rs` the two features. Its events reach the workspace through a channel (`BridgeEvent`) the workspace drains.
- Bound to `127.0.0.1` only; the token is 128 bits from the OS CSPRNG, 32 lowercase hex; an upgrade without the exact header `x-claude-code-ide-authorization: <token>` is a 401 before any JSON-RPC. The token is never logged. No path, selection, diff text, comment or token goes in a log line or a `sirio_perf` label.
- **Port and token persist** in the settings key-value table, so terminals that survived a restart (they live in `sirio_host`) still find a restarted Sirio. The saved port is bound again unless it is taken; "taken" means a connect to `127.0.0.1:<port>` is not refused (on macOS `SO_REUSEADDR` would let a loopback bind succeed next to a `*:<port>` listener), and the listener sets `SO_REUSEADDR` on macOS and Linux so a TIME_WAIT does not count (spec §10.15; Windows uses neither). Else a free port in 10000–65535 is saved.
- **The lockfile** is `<home>/.claude/ide/<port>.lock`, JSON exactly `{pid, workspaceFolders, ideName, transport: "ws", authToken, runningInWindows: false}` (`ideName` `Sirio`, `Sirio (debug)` in a debug build), written to a temp file then renamed, mode 0600 in a directory created 0700. `workspaceFolders` is the root of every worktree of every project in the sidebar, parked or not, rewritten when one comes or goes. **Only the file named by the port this instance bound is ever written or removed**: a file with that name left by a dead process is overwritten, nothing else in the directory is read, rewritten or deleted (Claude deletes dead-pid lockfiles itself; two Sirios never bind the same port). It goes before the listener is dropped, so no lockfile names a port nobody listens on while Sirio lives. Sirio never writes `~/.claude.json` or a Claude `settings.json`.
- **The switch** is the setting `claude.ideBridge`, default on, "Connect Claude Code to Sirio (/ide)" in the section that holds Claude Code's settings. Off: no listener, no lockfile, no variable in new terminals, existing connections closed (open proposals close as below). The bridge starts from `main()` after settings load and before the first terminal exists, never from the workspace's constructor, so in-process UI tests bind no port and write no lockfile; the lockfile directory is a parameter of `sirio_ide`. The port a new terminal is given lives in `ide_bridge::SSE_PORT` (0 = off), not in the control state.
- **The environment** is in [Agent adapters](agent-adapters.md): `CLAUDE_CODE_SSE_PORT=<port>` in every new terminal while the switch is on, never `ENABLE_IDE_INTEGRATION`, and the name is in `sirio_env::PER_PANE`.
- **Restart:** a Claude that lost its connection retries for about 15 to 25 s, then stays disconnected, and `/ide` does not bring it back (probe, spec §10.13 item 6). So when Sirio was closed for more than a few seconds, restart Claude in that terminal; the release notes must say so (the release-notes commit, written when the release is cut, carries the sentence). A Claude started afterwards connects at once.

## The owner of a connection

On `ide_connected {pid}` the app walks up from that pid (at most 32 parents, `sirio_ide::resolve_owner`, the parent lookup injected, `sirio_activity::process::parent_pid` on the background executor) until it meets the `shell_pid()` of a terminal Sirio holds, mounted or parked: that pane, and through it its worktree, is the owner. A connection keeps its owner until it closes; a connection whose pane is gone, or whose ancestry the platform cannot read, is ownerless and is resolved again when a worktree's terminals attach and before any owner-dependent action (a restart mounts only the selected worktree). An ownerless connection takes its worktree from the process's cwd (`/proc/<pid>/cwd`, Linux only; elsewhere none), gets diagnostics and `openDiff`, and gets no selection and no at-mention. Before `ide_connected`, requests are served as for an ownerless connection. Whether a hook, not a request, started a resolution is counted (`hook_resolutions` in the state), because a request that resolved the connection itself would make the ownerless cases of the E2E pass for the wrong reason.

## The answers

Every answer Sirio gives, all of them. Claude compares the strings byte for byte and checks only `content[0].text` (`content[1].text` must be a string for `FILE_SAVED`).

| answer | when, and only when |
|---|---|
| `FILE_SAVED` + the final text | the user's Accept (the text is the proposal, or the edited text with the file's line ending restored) |
| `DIFF_REJECTED` + `tab_name` | the user's Reject, or the Reject of the close confirmation |
| `TAB_CLOSED` | the result of Claude's own `close_tab` call, never of an `openDiff` (Claude reads `TAB_CLOSED` as an accept) |
| `CLOSED_<n>_DIFF_TABS` | the result of `closeAllDiffTabs` |
| JSON-RPC error `-32000` | a pending `openDiff` that `close_tab`/`closeAllDiffTabs` withdrew, or another `openDiff` with the same `tab_name` replaced; it carries no decision, and the probe confirmed Claude reads it as neither accept nor reject (the terminal prompt stays answerable) |
| method not found | any other tool or method, never a crash |
| `getDiagnostics` | one text item holding a JSON array, from memory, within 400 ms; past the deadline a JSON-RPC error, not `[]` (an empty baseline would make old errors look caused by the edit; the probe showed an error does not count toward Claude's three-timeouts cutoff, a timeout does). A per-file read of a file no live server has reported answers `[]`, not an error: an error would make Claude skip its after snapshot for every edit to a file Sirio has not open (spec §10.22) |

**Never decide.** `FILE_SAVED` and `DIFF_REJECTED` come only from Accept, Reject or the close confirmation's Reject; a connection that closes, a switch that goes off, a quit, a worktree or a project that is removed owes nothing, so none of them answers (an open proposal's question is asked first: closing never accepts). A test of the E2E (`no_decision_without_user`) reads each of those endings out of the client's transcript. If you add a code path that answers, it must start at a button.

**Coordinates sent to Claude:** 0-based line, UTF-16 `character`, end exclusive; `at_mentioned` lines are 0-based inclusive, so `FileViewEvent::SendSelectionToAgent.lines` (1-based inclusive) is converted with a subtraction. A selection's text is at most 4096 UTF-16 units, cut on a char boundary. `selection_changed` is coalesced per connection (100 ms in a release build) and always ends on the latest state; focusing a file tab sends its selection, focusing anything else sends nothing.

## The Proposal tab

`openDiff` opens `TabKind::Proposal` (`sirio_ui::proposal_tab`, `PaneContent::Proposal`, never saved) in the owner's worktree, in Secondary: title `✻ <file name>`, bar `Claude · <owner terminal's title> proposes a change · +a −d`, buttons `Edit` / `Show diff`, `Reject` / `Reject with N comments`, `Accept`. The body is the Changes view's diff (both modes, word highlights, the `+` comment affordance) of the file on disk against the text Accept would send (`ChangesSource::Proposal`, `sirio_git::diff_proposal`: both sides written to private temp files beside the database and `git diff --no-index`; an untrusted path never reaches git; the read, the canonical path and the 1 MiB cap are on the connection's thread). A proposal Sirio cannot draw (binary, over 1 MiB, a FIFO, unreadable) opens anyway, says why and keeps Reject and Accept: the terminal prompt must never point at nothing.

- Accept is inert and drawn disabled until the body shows the diff of the text it would send, so the user never accepts bytes they were not shown; Reject stays live. Accept writes the file's majority line ending (the original's; the proposal's when the original is missing or has none); the buffer is LF only.
- Edit swaps the body for an Ely editor (`proposal-editor`); once the text differs from the proposal the proposed side takes no new comments (their line numbers would name lines Claude never received). A dirty editor tab of the same file puts a warning in the bar.
- A proposal of a worktree that is not on screen is held tab-less in the workspace, parked with the worktree and never dropped by an eviction, and announced by a toast. A proposal arriving while the keyboard focus is inside Secondary joins the strip without unmounting the editor being typed in; anywhere else it becomes Secondary's shown tab (spec §10.23).
- **Every way of closing** a proposal tab (its ✕, Ctrl+W, the tab menu, Close Others and Tabs to the Right, `surface.tabs.close`) and closing a worktree or project that holds one asks once, "Closing rejects Claude's change" (Reject / Cancel), before anything else closes or any session ends; the release `workspace.close` verb, which cannot ask, refuses while a worktree holds one. The question holds tab identities, not positions.

**Delivery: the clipboard is the only one.** The probe found that a paste of more than 3 lines or about 800 characters collapses to `[Pasted text]` in Claude's prompt, so Sirio never types into the terminal (the narrow exception of spec §4.8 was not built). The comments are copied already formatted, one per line, `@<path>#L<n> <comment>` (the path relative to the worktree, `#L<a>-<b>` for a range, `(proposed) ` before the text of a comment on the proposed side, a newline in a comment turned into a space), with the toast "Comments copied: paste them into Claude". **Every way a proposal ends delivers its committed comments once, and a draft is never delivered**: Reject (bar or confirmation), Accept, `close_tab`, `closeAllDiffTabs`, a replace, a disconnect. A `closeAllDiffTabs` is one `BridgeEvent::DiffsWithdrawn` carrying every withdrawn id, one joined copy and one toast, with no UI time window. Accept still answers only `FILE_SAVED`. `deliveries` in the debug state counts them.

## Claude's side, as probed (spec §10.13)

Against the real Claude Code 2.1.325 (the live mode re-checks it against whatever is installed):

- With `CLAUDE_CODE_SSE_PORT` set Claude connects about 1 s after the listener is up, offering `Sec-WebSocket-Protocol: mcp` and the token header, then sends `initialize`, `notifications/initialized`, `ide_connected {pid}`, `tools/list`. A lockfile whose port equals `CLAUDE_CODE_SSE_PORT` is taken without a folder match, also under `TERM_PROGRAM=vscode` and beside a decoy lockfile for the same folder.
- A diff trap: with any IDE connected and `diffTool` left on `auto`, every Edit/Write prompt hides its inline diff and calls `openDiff`; nothing checks the IDE offers it, so a bridge without a working `openDiff` blinds every approval. The terminal shows `Opened changes in <ideName> ⧉`.
- Per Edit: `closeAllDiffTabs` at the start of every turn, `openDiff {old_file_path, new_file_path, new_file_contents, tab_name}` (`tab_name` is `✻ [Claude Code] <file> (<6 hex>) ⧉`, new for every proposal), and after **every** answer (accept, reject, error) `close_tab`, twice for accept and reject. Then `getDiagnostics {uri}` with the file still holding the old text (the pre-write baseline), then `getDiagnostics {}` once it holds the new one; if the per-file call fails or times out there is no after snapshot, and after three consecutive timeouts Claude stops asking.
- `DIFF_REJECTED` ends the turn (the pane says `User rejected update to <file>` in 2.1.325 and `Rejected update to <file>` in 2.1.326); no hook fires for a minute except an idle `Notification`, but OSC 7501 reports `idle` at once. A dropped socket with an `openDiff` pending leaves the prompt answerable, so no answer is owed.
- Headless Claude (`-p` stream-json, the native chat) never connects through a lockfile and never calls `openDiff`: that is a separate project and a separate transport.

## The debug verbs

Debug builds only (`served::DEBUG_METHODS`, the `surface.ide.*` arms in `sirio/src/main.rs`, all behind `cfg!(debug_assertions)`; a release build neither lists nor answers them, and none answers Claude in a release build):

- `surface.ide.state`: `enabled`, `port`, `lockfile` (the file's name, never the token), `connections` (`conn`, `pid`, `owner_pane`, `worktree`), `proposals` (per proposal `tab_name`, `conn`, `worktree`, `on_screen`, `ready`, `dirty`, `refusal`, `editing`, `comments`, `cards`, `composer {side, line, in_view, draft_len}`, `reject_label`, `owner_named`, `counts`), `confirmation` (the open "Closing rejects" question), `toasts`, `hook_resolutions`, `last_delivery`, `deliveries`, and the three keys the focus cases read, `secondary_shown` (1-based position of the tab Secondary shows), `secondary_focused` and `prompt_up`. Three builders make the state; an agent adding a field edits the one that owns it: `control_ide_state` (`main.rs`, the three extra keys), `IdeBridge::state_json` (`ide_bridge.rs`) and `ide_proposals_state` (`ide_bridge/proposals.rs`).
- `surface.ide.switch on=true|false`: the Settings switch.
- `surface.ide.act action=accept|reject|edit|show_diff|close|confirm_reject|cancel|close_worktree|remove_project|close_others` (`tab_name`, `text` optional): presses what a user presses.
- `surface.ide.comment tab_name side=old|new line [end_line] text [commit=false]`: opens the composer at the anchor, sets its text and adds the comment (`commit=false` leaves a draft).

The debug-only knobs, read under `cfg(debug_assertions)`: `SIRIO_DEBUG_IDE_START_DELAY_MS` (each listener start holds its bound port that long, so a start stays in flight while the switch flaps), `SIRIO_DEBUG_IDE_SEND_AFTER_MS` (widens, never narrows, the 100 ms selection window) and `SIRIO_DEBUG_IDE_RESOLVE_AFTER_MS` (delays the first resolution a connection's announcing itself starts, never one a request runs).

## Proving it

`Scripts/Tests/test-ide-bridge-e2e.sh` (see [e2e-tests](../e2e-tests.md)): a stand-in client (`Scripts/Tests/ide_client.py`) runs in a real terminal tab of an isolated debug Sirio, so owner resolution is real; its `--live` mode runs the real `claude` against `fake_messages.py`, by hand only. macOS, the release platform, is checked by hand: a debug build, `claude` in a terminal, the connection owned by its pane in `surface.ide.state` (libproc `parent_pid`), one Accept.
