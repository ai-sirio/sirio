# Agent activity detection — layered evidence, not one signal (`sirio_activity`)

Whether a pane shows as running/idle/needs-input is resolved from independent evidence layers (A to D below, and the agent's own reports above them), weakest overridden by strongest as it arrives — ported byte-for-byte in intent from the original Swift `AgentActivityModel`, and `sirio_activity` carries no GPUI dependency, so this stays pure state-machine logic testable without a window:

- **Layer A — `sirioctl notify` hooks.** Authoritative when present. Agents with `has_native_hooks() == true` call `sirioctl notify --session <paneId> --status <status>` themselves (user-global hooks omit `--session` and let sirioctl read `SIRIO_PANE_ID`); a recent Layer-A push suppresses Layer B for a debounce window (`should_apply_title_signal`, `sirio_activity::title`).
- **Layer B — OSC terminal title.** `identify_agent_from_title` assigns an unregistered pane's agent identity from its title text; `detect_status_from_title` reads status from the same title using each CLI's own convention. Every CLI has its own title format, captured empirically, not guessed: Claude idles as `✳ …`, works as `. …`, a braille spinner or, in 2.1.316, `◐ …`/`◑ …`; Pi titles `π - <cwd>`; its omp fork titles `π > <cwd>` when idle and `π ⠋ <cwd>` (a spinner after the glyph) while working, and `π:` in older builds (a `π` followed by `:`, ` > ` or a spinner is omp, any other is Pi); Codex 0.144+ also writes a braille "dots" spinner into its title while working — a bare spinner alone is therefore ambiguous between Claude and Codex and must **not** be used to assign identity (`contains_braille_spinner`; both are caught by Layer D instead).
- **Layer C — content signal.** `detect_content_status` matches live pane scrollback content on output-settle; not debounced against Layer A, since a genuine content match is closer to ground truth than a stale title.
- **Layer D — foreground process.** `inspect_foreground_agent` (`sirio_activity::process`) walks the pane shell's direct child processes via `/proc` and matches comm names against the catalog. This is the only signal that catches agents with no usable title convention. Node/Bun-hosted CLIs (pi, omp) are invisible here and rely on Layer B instead.

Pane ownership determines who is allowed to clear a pane's status, and matters when changing this code: **spawn-owned** (Sirio launched it — cleared by watching process exit), **title-owned** (cleared only when the title stops matching that agent's conventions), **process-owned** (Layer D — cleared only by `AgentActivityModel::process_gone`, never by an unrelated title change), **program-owned** (the host named the pane's foreground program, or a report's `app=` named the agent on a pane that had no identity — cleared only by `program_gone`, which the app runs after `program_exited`). Mixing these up reintroduces bugs where one layer's signal (or absence of one) wipes state that another layer is still relying on.

**The agent's own reports (OSC 7501) — the layer `resolved()` asks first.** An agent that reports its state over OSC 7501 (the host scans the PTY and sends `ProgramStatus` events) is the best evidence there is, so a pane that holds a report record shows only what the record says, `None` included, ahead of Layer E and A–D. `sirio_activity::report::TurnTracker`, one per pane, turns reports into a status on the **host's clock** (`at_ms`, milliseconds since the session started, so an app stall or a relaunch cannot change a turn's length): `working` opens a turn and is Running; `blocked` is NeedsInput, a first one included, and does not end a turn; `done` and `error` are Done and Error and close the turn; `idle` with a turn open is Done when it lasted at least `MIN_TURN_MS` (or a `blocked` came inside it) and otherwise shows no status, which is what silences Codex's 10 ms blip and a startup dialog; with no turn open a Done or Error stays (Codex sends an `idle` right after every `done`, and the finish must not be wiped), a `blocked` outside any turn clears, and no status stays none, which is what silences a startup `idle`; `clear` removes the record and the layered status under it. A report older than the one held is a replay (events queued across a reconnect arrive after the seed) and is ignored, the same report again changes nothing, and a clear always applies. The host sends a status only when it changed (a report that leaves the record and its stamp as they are is no event: `owner.rs`, and `host.md`), so a program repeating `working` per tool is not a frame per report. The record is kept per pane apart from identity, so a report that arrives before the program is named is not lost: it shows once the identity lands. While a record is live a hook (`notify`) sets no status, a program-owned pane's title and screen set none either, and a non-agent foreground program does not clear the agent (an agent running a tool).

- **Startup is silent.** A program-owned pane's title and screen (Layers B and C) set no status for `TITLE_GRACE` after the agent is recognised, and none while a record is live. An agent that never reports (an older Claude or Codex, any CLI with no 7501; Pi 1.4.0 reports once its probe is answered) gets today's title mapping after the grace. A title can reach the app before the program event that names the agent, so in a session that has already named a program (`is_program_session`, set by the first `Program(Some(_))`, the shell's pre-exec copy included) a title that identifies an agent assigns the identity only, with no status, and a title-owned pane in such a session is as silent for `TITLE_GRACE` as a program-owned one. While a record shows, no title clears the pane's identity.
- **Exit order.** When the program leaves (`Program(None)`, or the session's child exits), `subscribe_terminal_activity` runs `program_exited` (a pane Running by report settles to Done), then `drain_activity_transitions` so that Done is found as a stop while the pane is still an agent's, then `program_gone` clears the identity. Reversing it loses the stop: `pane_is_agent` is false once the identity is gone.
- **A record lives as long as its session.** When the session's child exits (`ChildExited`) or the host is lost (`SessionLost`) the app runs `program_exited`, drains, then `drop_report`, whoever owns the pane; the owner's own handling follows (a program-owned pane clears with `program_gone`, a spawn-owned one shows its exit code). A spawn-owned pane that exits non-zero mid-turn skips the settle, so its stop is one Running → Error and not Done then Error. The record's last status becomes the layered status at the drop, so nothing flips between the two steps. A new session restarts `at_ms` near zero, which a kept record would treat as a replay. A different agent replacing the standing one drops the old agent's tracker, and so does Layer D losing its agent: `process_gone` takes the record with the identity, and the Layer D loop first runs `program_exited` and drains the stop, then `drop_report`, then `apply_process_signal` clears the identity (the same order as an exit; settling after the identity is gone loses the stop), so the next agent Layer D names in that session starts with no record and its startup `idle` closes no turn of the last one's. A `Program(None)` ends something only when the pane's last `Program` event named a program (`is_program_running`, set by `Program(Some)`, cleared by `Program(None)` and when the session ends, so a Restart under the same pane id starts clean): a reconnect's re-seed sends one for a session that never named a program (a Sirio-spawned agent, every Windows pane), or whose last event was already a `None` (an agent `exec`ed in a shell that had run a job: it takes the shell's group, so the host names nothing), and it is no exit. An agent that exits while the client is disconnected still settles on the re-seed: its last event was `Some`.
- **Status with no identity.** A record shows only on an agent pane (`record_shows`: record and identity), so one that waits for its identity swallows no hook. A report's `app=` names the agent of any pane that has none yet (Windows, a Sirio-spawned `$SHELL -lc <agent>`, a launcher the resolver misses, a report that beats the program event); a `Program` that names an agent decides afterwards. Only a session that has named a program stops Layer D (`is_program_session`), and `Program(None)` calls `process_gone` only for a pane whose last `Program` event named one (`is_program_running`). On Windows, which names no program, an identity a report gave clears when Layer D, having seen the agent's process on that pane (`note_process_seen`), sees none (`process_lost`; `program_exited`, drain, `program_gone`, in the Layer D loop), and when a `ProgramStatus(None)` clears the record (no stop). A Node or Bun agent that Layer D never sees keeps its identity until the shell exits.
- **A cleared status is not a transition**, so `take_cleared_panes` hands the app the panes that went from a status to none and `drain_activity_transitions` refreshes their running flag; without it a turn too short to count would leave its session reading as running.
- **OpenCode reports through its server, not the terminal.** OpenCode v2 sends no 7501; `sirio_opencode_watch` reads the state of its sessions from the service its TUI talks to (the registration file `$XDG_STATE_HOME/opencode/service.json`, confirmed by `/api/info`, then `GET /api/event`), and `sirio/src/opencode.rs` links each `opencode` pane to a session only when sure (the pane's title is `OC | <session title>`, or it is the only `opencode` pane in its folder and exactly one session there was created after it started) and writes the session's state into the pane's record with the server's own timestamps. A pane keeps its link while the linked session has no title yet, whatever other session has the pane's `OC | <title>` (the TUI's title can beat the service's rename by milliseconds; the next relink after the rename decides by title), and while the held session is in the folder and has the pane's title even when an older session of the folder has it too (a generic title such as "Greeting": among several, the held one wins). The service's own end of an execution (`session.execution.succeeded`, `.interrupted`) is a finish (`OcState::Done`, reported as `done`, so `MIN_TURN_MS` does not hide a sub-second turn) and `.failed` is Error; `Idle` stays for a session the list reports as not running. A pane that newly links to a session never takes news from a finish: `relink` reports its Done or Error as Idle, whatever its time (the turn predates the pane, or belongs to a sibling pane in the folder), and the turns that follow report normally. A failed per-session permission or question lookup means not waiting, never a failed seed. The watch's two HTTP agents follow no redirect. That link is the only writer of such a pane's record: the host's `ProgramStatus` for an `opencode` pane is ignored (every one is a none, a reconnect's re-seed included, and would wipe it). The watch runs only while a pane's program is `opencode`, logs a failure kind once per run (`[opencode-watch] <kind>`, never content) and on any failure unlinks every pane: the mark stays, no status. The title the host's engine holds travels with the attach seed and the reconnect re-seed as its own event (`TerminalActivityEvent::SeededTitle`, never an `OscTitle`: that would run Layer B at a relaunch), and only `opencode.rs` reads it, so a relaunched app still links a pane whose session was titled.
- **Below 7501 nothing changes.** Hooks, titles and the process exit code map exactly as before, and a pane with no record is resolved exactly as it was. The three states are told apart only where an agent reports.

**Unread sessions — one funnel, one stop rule.** Every resolved status change of every pane, whichever layer produced it and whichever worktree the pane is in, is queued by the model and handled by `SirioWorkspace::drain_activity_transitions`; nothing else decides about an unread mark or a notification. Whether a change is a *stop* is decided only by `sirio_activity::StopPolicy::decide(old, new, first, on_screen)`, a pure function: a move from Running to a settled status, a move into Error, or a first status that a restored or unrecorded session makes a stop; moves between settled statuses and into Running are not stops. Only agent panes stop (a chat, a pane with an identified agent, or one an agent's hooks have pushed to), so a plain shell's exit marks nothing. A stop that is not on screen marks the session unread and posts one notification (a stop found at restore marks without posting), and the same decision is made for chats and terminals alike. Only seeing a session clears the mark (`mark_shown_sessions_seen`, run by the frame that draws it and when the window is activated), and closing the tab, the worktree or the project forgets it. The mark and the last known running state are saved per tab by `persistence_id` (`set_tab_attention`), so they outlive a restart.

A stop is found for every session the app can reach, not only the mounted ones. After a relaunch only the selected worktree is mounted, and a host-kept agent in any other keeps sending hooks, so `session_for_pane` falls back, after the mounted, retained and parked tabs, to an index of the persisted layouts of the worktrees none of those hold (`unmounted_sessions`): one pane key names one session, and the index is rebuilt from the database only after `invalidate_unmounted_sessions` marks it stale (a catalog change, a switch, an eviction, a close, a pane-id dedup, an adopted terminal), never per transition or per frame. A hook this run pushed to a pane proves its agent is alive now, so its first decision is a live one and not the restore the previous run's record would make it (a stop found by the process sweep, with no hook, stays quiet). Settings covers the window, so a session under it is not on screen. So does the Primary rail (`primary_rail_drawn`): while the Primary half is collapsed to it, a Primary tab is on screen only as the open peek's tab, and while a peek is open it is the only tab on screen: the card covers most of the Secondary, all of it in a narrow window (`session_on_screen` is the one place this is decided, and `mark_shown_sessions_seen` and every notification decision go through it). The rail's icon carries the unread ring and dot like the sidebar's pill, and `surface layout read` reports its unread positions as `railUnread`. The tray follows the unread marks and the parked strips without a frame (`refresh_worktree_unread`, `refresh_parked_tray_panes`), because a minimized window paints nothing.
