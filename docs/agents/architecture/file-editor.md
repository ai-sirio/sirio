# File editor on Ely (`sirio_ui::file_view`, vendored `ely-gpui-component`)

The file tab draws and edits its code with Ely's `CodeEditor`, and the two halves keep a strict division: `CodeEditor` owns the text on screen and what the keyboard does, `Editor` (`sirio_ui::editor`) owns the disk (load, save, external change, conflict, snapshot) and the Markdown operations. Text flows `CodeEditor` → `Editor` on every `Changed`, and back through `reset_keeping_view` (a reload, a disk adoption; the caret and scroll stay) or `edit` (a Markdown op, one undo step) — `file_view/code_surface.rs` holds both directions, and `file_view/sync.rs` the minimal edit that carries a change across. The buffer is LF only: `sirio_markdown::Document` reads the file's line ending (`LineEnding`, re-exported from `sirio_ui::editor`), keeps it, and writes it back on save, and the code editor normalises a paste or an IME commit to LF so it never holds a `\r`. Colour is Ely's per-line highlighter hook fed by `sirio_syntax` (bezel's spans, `code_spans`) through a bounded per-line-text `SpanCache` that rotates once per render, so Ely's own lexer never colours a file; the git marks in the gutter are `sirio_git::diff_entry(.., 0)` (no context lines, `--inter-hunk-context=0`), fetched off the thread with one request in flight and one trailing re-run, and a mark opens its hunk in place. A breadcrumb row (the path, then the language server's symbols around the caret) and the find bar are docked above the code, in that order, not floating over it, and the status row below carries the branch, the server, the caret, indent, line ending, language and the notification bell; a snapshot (a change request's file at a revision) is read-only with one banner of Sirio's own (`without_read_only_banner`). Everything that is Sirio's own on top of Ely is a local change recorded in `rust/vendor/ely-gpui-component/LOCAL-CHANGES.md`, which also names the pinned revision (`e17e31a6`, not on upstream `main`), the ports from `main` and what is not vendored — read it before a sync, and keep each hook it lists (`select_in_place`, `reset_keeping_view`, `diagnostics`, the read-only banner, hard tabs, the pointer leaving the code, the sideways scroll: a line wider than the column scrolls under a gutter that stays put, with the wheel, Shift and the wheel, a bar, and the caret). The editor's keys are Ely's, bound only in the `ElyEditor` context by `init_editor`; `ctrl-alt-up/down` stay Sirio's pane focus (add-cursor is `shift-alt-up/down`), an empty-selection Copy hands the chord on, and Escape is `SingleCursor`, which `FileView` captures to close find or an open hunk first. The performance record is `docs/perf/2026-10-ely-code-editor.md`: the cost that grew with the file's length is gone, and a constant 1.4–2.5 ms per typed or scrolled frame (median) over main remains, accepted; the one visible difference is that the minimap of a file taller than itself shows one sampled line per pixel row instead of blending every line. **The drawer** under the code (`sirio_ui::drawer`, `WorktreeDrawer`) is one per worktree, not per tab: Problems and Search tabs, `secondary-j` toggles it and `secondary-shift-f` opens Search (both in the `FileEditor` context, so Ctrl on Linux and Windows and Cmd on macOS), its height (default 240 px, 96 px minimum) and open tab are persisted in `editor_drawer` (v24, keyed by the worktree's path string) and a parked worktree keeps its drawer, problems and search across a switch. **Problems has one store**, `ProblemStore`, which feeds both the gutter marks of every open file view and the list: worktree-relative paths, every server's findings for a file, fed by each publish and by a view's load; a server that ends goes through `language_server_gone` and `LspSupervisor::forget`, and its findings vanish and it stops being named. Only *errors* open the drawer, by identity `(server key, worktree-relative path, message)` against a persisted seen set that moves only while Problems is shown (once, 250 ms after the last publish of a burst) and when the drawer closes (`ErrorAlarm`, spec §4.4); Problems draws at most 1 500 rows, built once per store change, and says how many more are not drawn (its tab label and toggles keep the exact counts, through the vendored `ProblemsPanel::counts`); it has three accepted costs, written there: an error the user saw, fixed while not looking and returning identically does not reopen it, a close landing between a server's clear and its republish reopens it once, and a quit inside the 250 ms pause after a burst seen in Problems reopens it once at the next launch. **Search** (`drawer::search_engine`) lists the worktree as `git ls-files -z --cached --others --exclude-standard` does, matches the whole LF-normalised text with Ely's `Finder` and `GlobFilter` (vendored, split out of `find_all`/`passes`), skips and counts files over 1 MiB, binary and non-UTF-8 (a listed name that is not UTF-8 included), and skips symlinks silently (never followed, so no text from outside the worktree reaches a result); it stops at 20 000 matches and says so, a dirty buffer is searched instead of its file, and results are not live: opening a hit re-checks the match against the target's current text and shows only its line when it moved. **Replace all** is literal (`$1` stays `$1`, as the in-file Replace), skips unsaved (the tabs dirty at the press, and again, through a live handle the workspace keeps current, immediately before each file is written), symlink, outside-the-worktree, read-only and not-a-file paths and names each in a report, leaves every byte outside a match as it was (a mixed-ending file included), keeps the file's mode through `write_atomically`, and is disabled while capped or with an empty field; macOS has no file watcher (`FileSystemEventMonitor` is unsupported there), so Replace all itself tells each open clean tab to adopt the new text through `check_external`, and the debug switch `SIRIO_NO_FILE_WATCH` (the E2E's `--no-file-watch`) reproduces that on Linux. `Scripts/Tests/test-editor-e2e.sh` and `Scripts/Tests/test-ely-editor-probe.sh` prove it, and what neither covers is checked by hand: macOS keys (and `Cmd+J` / `Cmd+Shift+F` in particular), `Ctrl+Shift+F` reaching the app on Windows (#374), a real input method (and the drawer's fields), and the ⚠ in Problems' label, which draws as a colour emoji on Linux.
