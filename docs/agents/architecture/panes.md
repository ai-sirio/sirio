# Pane hierarchy

`SirioWorkspace` (`rust/crates/sirio/src/main.rs`, the `gpui::Render` root) holds the open tabs/panes and a `Vec` of workspace rows (project/worktree/branch/path, each with a `mounted` bool) — the Rust equivalent of Swift's `Project -> [Worktree]` plus `openWorktreeIds`. A worktree's `mounted` flag tracks whether its terminal hosts stay mounted (attached to their sessions) across sidebar selection changes; this is a live contract other code depends on; see the `tab_has_live_foreground_process` comment in `main.rs` for a case where an activity-model shortcut nearly broke it. Terminals are host sessions (SP2): the PTY, the resident VT and the journal live in `sirio-host`, and a `TerminalView` holds a `HostLink` to one. **Quit detaches.** `PaneRegistry` (`sirio_control::panel`) owns no PTYs; it keeps the app's own panes — the in-process `LocalLink` fallback — and the control-session entries that feed sidebar status. On app quit (`cx.on_app_quit`), `PaneRegistry::shutdown` forgets the app's panes and ends nothing, and the host's sessions keep running. A plain window close only flushes session state (`cx.on_window_closed`). Dropping a `TerminalView` **detaches** (its `Drop` calls `detach`, never `end`), and so is eviction of an unmounted worktree from `TerminalPaneCache` meant to (but see the end of this paragraph: no view is dropped today). Closing a tab, a worktree or a project ends its sessions: closing a worktree or project `term.close`s its control sessions (`PaneRegistry::shutdown_for`, then `end_control_sessions`) and every `origin: app` session it owns (`end_app_sessions`, off the GPUI thread): the sessions whose cwd the deepest worktree holds, and, for a session no known worktree holds, those its persisted or parked layout names, attached parked panes aside (`host_sessions::app_sessions_to_end`; a layout id alone never ends another known worktree's session, because a stale id can still name one). Selection changes and cache eviction are meant to only detach. A **Show session** tab (palette "Show Session: …", `sirioctl panel show <id>`, app only) is attached, not owned: it never creates or closes a session, its close detaches, it shows *Session lost* without Restart if the session vanishes, and it is never written to the saved layout (a parked worktree keeps it). The centre's Secondary half is drawn only while it holds a tab and is not hidden (`secondary_pane_visible`); an empty one is never drawn, and what its tile launcher offered lives in the right panel's **Open** view (`sirio_ui::right_panel::open_list`, opened through `SirioWorkspace::open_surface`). Dragging a movable tab right while the pane is absent shows a drop zone as wide as the pane will be. `docs/superpowers/specs/2026-10-15-secondary-on-demand-design.md` has the design; `Scripts/Tests/test-open-list-e2e.sh` proves it. A tab no terminal's link runs for (a restored tab not shown since a relaunch, or any tab of a worktree not selected since) still reports its program and status: the app's `host_programs` listener feeds them to the activity model, and a running terminal link stays the only route for its session. (Eviction is meant to detach, but no terminal is released today: `TerminalBindings` holds a strong handle to every bound terminal for the app's life, so an evicted worktree's tabs keep their links and notify through them.)

While the Secondary half is drawn, the Primary half can be **collapsed to a rail** (`primary_pane_collapsed`, stored per worktree like `secondary_pane_hidden`, v25): a 40 px column of its tabs' icons with their status dots, an expand button on top and the New menu's `+` at the bottom, while the Secondary takes the rest of the centre (`panel_layout::resolve_collapsed_center`). `SirioWorkspace::primary_rail_drawn` is the flag *and* `secondary_pane_visible`, and the flag never outlives the Secondary half: every path that stops drawing the Secondary clears and persists it (`clear_primary_collapse_if_secondary_gone`). A click on a rail icon **peeks**: that tab's own view is drawn in a floating, opaque panel over the Secondary, as wide as the expanded Primary half would be, and the peek is the only place that view is drawn in that frame. Every other route that makes a Primary tab active on a user's request peeks it too, through one hook, `peek_active_primary_tab`, called by `select_tab` and by the paths that create a chat or a terminal; restores never call it. An open the user did not ask for (Follow Edited Files, `browser.open` over the socket) lands as the Secondary's active tab under an open peek, which keeps the keyboard (`keep_peek_over_open`). The peeked tab is the active tab; with the rail drawn and no peek open, a Primary tab never is: `settle_primary_peek`, at the top of every render, closes a peek whose tab is no longer the active one and hands the active tab back to the Secondary. Esc never closes a peek: it belongs to the peeked terminal or chat. Collapsing changes what is drawn and nothing else: the tabs stay in `self.tabs`, `TerminalPaneCache` keeps their entities, activity keeps feeding their status, so no chat or terminal is detached, parked, paused or throttled because the half is collapsed — the same way a Secondary half hidden with Ctrl+Shift+B keeps running. `docs/superpowers/specs/2026-11-01-primary-rail-design.md` has the design; `Scripts/Tests/test-primary-rail-e2e.sh` proves it.
