# Agent adapters (`sirio_agents`)

Every supported CLI implements the `AgentAdapter` trait (`id`, `display_name`, `has_native_hooks`, `prepare`, `command`, `resume_command`). `sirio_agents::ALL` is the fixed list of 5 adapters, in display order. An adapter's ACP claim (`builtin_acp`) covers only its own binary's subcommand — verified, defaulting to `None`; everything reachable through a separate package resolves through `sirio_registry`. `prepare` writes only worktree-local files, its hook config and the skill, and **never** touches user-global config (`~/.claude/settings.json`, `~/.codex/config.toml`, etc.). The writers outside Sirio's own data are explicit buttons and three startup steps (the third is OpenCode's, below), never a pane. Settings → General → **Install Hooks** (`install_global_hooks`, a trait method defaulting to `NotSupported`) writes the hooks: Claude merges the five hook arrays into `$CLAUDE_CONFIG_DIR`/`~/.claude/settings.json`, Codex sets `notify` in `$CODEX_HOME`/`~/.codex/config.toml` via `toml_edit` (format-preserving), OpenCode writes `~/.config/opencode/plugins/sirio-session.js` only for a confirmed OpenCode 1.x (the verdict is the major version `opencode --version` reports, run in the selected worktree, never the service registration; under 2.x, and when the binary gives no readable version, it writes none and removes the file only when it is Sirio's own generated global plugin, naming the path in the report; any other file there is left byte for byte; under no readable version the report says `OpenCode: no hook needed — OpenCode did not report its version, so no plugin was written`; the version memo never unlearns a version read earlier in the run, so a slow or failed probe changes nothing). "Sirio's own generated file" means exactly the generated text: the template of `sirio_agents/src/opencode.rs` (`PLUGIN_TEMPLATE` for the worktree file, `GLOBAL_PLUGIN_TEMPLATE` for the global one, and `LEGACY_PANE_PLUGIN_TEMPLATE`, the worktree text older builds wrote, which named one pane) with `__SIRIOCTL__` replaced by a one-line JSON string literal and, in the legacy text, `__PANE__` by `pane-<digits>`, every other byte equal; a file with Sirio's header line and anything else is the user's and is left byte for byte. A file an older build wrote in any other shape is not recognised, so it stays. The startup step: when the app's version probe reads 2 or more, it removes Sirio's generated global plugin (the same exact match), because OpenCode 2 refuses it and no button would take it away, and logs `[sirio] opencode: removed Sirio's generated global plugin (OpenCode 2 refuses it)`; Pi and omp honestly report no user-global mechanism. Those hooks carry **no** `--session`: `sirioctl notify`/`session-ref` fall back to the `SIRIO_PANE_ID` every Sirio pane exports and exit 0 silently outside one (no pane, or no socket), so a global hook never surfaces an error inside an agent Sirio did not launch. Adapters that generate command-line overrides embedding JSON (Codex's `-c notify=[...]`, omp's hook file) share `json_string_literal` in `sirio_agents/src/shell_quote.rs` — it must build a JSON string literal without escaping slashes, because Codex's `-c key=value` override is parsed as **TOML**, and `\/` (JSON's optional slash-escaping) is not a valid TOML escape. Getting this wrong makes Codex fail silently at config load, before it ever reaches its TUI. OpenCode's session ref, the id a relaunch resumes with (`opencode --session <ref>`), has two sources, decided by the binary's `opencode --version` (`sirio_agents::opencode`, memoized for the process: probed off the UI thread, in the folder the pane runs in so that a version manager's per-folder choice (mise, asdf) is the pane's, at startup, at each fresh OpenCode tab and at Install Hooks; a restored OpenCode pane waits for the first probe, and a fresh tab decides on its own probe's answer). Never by `service.json`. OpenCode 1.x: `prepare` writes the worktree-local plugin `.opencode/plugin/sirio-session.js`, which reports the id through `sirioctl session-ref`; it names no pane, one file serves every OpenCode tab of the worktree, so it reads the pane from the `SIRIO_PANE_ID` of the `opencode` process that loads it (and reports nothing without one). OpenCode 2.x (or later), or no readable version: `prepare` writes no plugin and removes `.opencode/plugin/sirio-session.js` only when it is Sirio's generated one (the exact text, the current one or the legacy one that names a pane, `LEGACY_PANE_PLUGIN_TEMPLATE`) (OpenCode 2's TUI shows "Plugin failed" for it); a fresh tab then reads `$XDG_STATE_HOME/opencode/service.json`, checks `GET /api/info` (the pid matches, the major is 2 or more) and sends `POST /api/session` with `{"location":{"directory":<the tab's worktree>}}`, all within one 3 s deadline off the UI thread. With the reply's id Sirio writes it as the pane's ref and launches `opencode --session <id>` (plus `--prompt` for a hand-off). Any failure (v1, no answer, service down, non-200, timeout, a reply for another directory) launches plain `opencode` with no ref. Titles write no ref at all: a typed `opencode` has none. A fresh terminal tab deletes the row under the key it takes (the code deletes for every new terminal tab, plain and Show included; it looks in the app's in-memory copy of the rows, every row loaded at startup or written through the app since, and touches the database only when that copy has one, so the common tab open writes nothing from the UI thread, and a row another connection writes while the app runs is not seen), for every agent, because a pane id is reused and a stale row would resume in the new pane; an OpenCode 2 tab saves its created session under its key only when no other session names that key, and otherwise deletes the row there, so that a tab running `--session <id>` never keeps another pane's row. Limits: the ref does not follow switches made inside the TUI (`/new`, `/sessions`, its tabs), it stays on the session Sirio created; after a reboot the service is down, so the first OpenCode tab launches plain and gets no ref (that `opencode` starts the service); a session the user never prompts in stays behind, empty and untitled; an id several layouts name, when the startup dedup did not run (the host did not answer at startup), can still get a row written by one worktree's live pane during the run and resumed by the other's restore if that first worktree is no longer parked at the switch; the version memo is one per process, so worktrees pinned to different OpenCode majors are told apart only by a fresh tab's own probe; restored OpenCode panes wait for the startup probe (75 ms on 2.3.0, at most 5 s), those whose session the host still runs included. Codex, pi, opencode and omp `prepare` write `.agents/skills/sirio/SKILL.md` in the worktree, from the copy the binary ships, and the app keeps that file out of git through the common dir's `info/exclude` (`keep_agent_skill_out_of_git` in `sirio/src/main.rs`, for `SHARED_SKILL_ADAPTERS`); Claude writes `.claude/skills/sirio/SKILL.md`, and that folder is not excluded. The skill is no longer installed with `npx`. **Install Skill** writes the user-level copy for each CLI, at the paths `sirio_agents::user_skill_paths` names: `<CLAUDE_CONFIG_DIR or ~/.claude>/skills/sirio/SKILL.md`, `~/.agents/skills/sirio/SKILL.md` (Codex, Pi and Oh-My-Pi read it together) and `<XDG_CONFIG_HOME or ~/.config>/opencode/skills/sirio/SKILL.md`; a file without the managed marker is never replaced. The startup refresh rewrites only a copy Sirio already wrote, and only when it differs from the bundled skill; a debug build runs it only with `SIRIO_CLI_AS_RELEASE=1` (`cli_install::stable_is_debug`).
