# Control socket (`sirio_control`)

`ControlServer` listens on a unix socket (`$SIRIO_SOCKET` if set, otherwise `$XDG_RUNTIME_DIR/Sirio/control.sock`, falling back to the XDG state directory when no runtime directory exists) and dispatches line-delimited JSON `ControlRequest`s to a `ControlHandler` the app (`sirio`) implements. This is both the `sirioctl` CLI's transport and how agent lifecycle hooks talk back to Sirio (Layer A of [activity detection](activity-detection.md)). `PaneRegistry` (in `sirio_control`, not the terminal crate) is the shared source of truth for live panes that both the control handler and the foreground-process walk (Layer D) read from. Its method groups — panel.*, workspace.* (worktrees), project.*, pane.* and tab.*, surface.*, browser.*, notification.*, system.* (ping/capabilities/identify), session.* and a few singletons — are all dispatched from `rust/crates/sirio/src/main.rs`, and `sirioctl capabilities` lists the full set a running instance serves; the flat kebab sirioctl commands (`list-workspaces`, `new-workspace`, `select-workspace`, …) mirror cmux's CLI names. `panel.*` is also answered by the host (SP2): the app forwards every `panel.*` to the host, `sirio_control::host_panels` is the translation both sides share, and the app adds only the layout fields it alone knows. `sirioctl` asks the app first and goes to the host only when the app's socket is missing or refuses (`sirio_control::route`); a socket that accepts and stays silent is waited for, never bypassed to the host, because loss of contact is not evidence of death. With no app and no host it prints "Sirio is not running and no host is up" and never starts one; `--worktree` needs the app. Debug builds also serve `surface.host.end_all`, `surface.terminal.open`, `surface.open_list.open`, `surface.chat.panel`, `surface.chat.effort`, `surface.settings.act` and `surface.terminal.state` (whose `agentStatus` names the pane's status word), which release `capabilities` omits; `surface.layout.read` (whether the Secondary pane is drawn, each half's tabs, the right panel's view) serves every build. `sirio_control::served::served_methods(debug)` is the one list a build serves, and `system.capabilities` passes it `cfg!(debug_assertions)`. `sirioctl --dry-run` prints the one JSON request it would send and contacts nothing; `panel wait` exits with the waited child's code. The stable copy is `<data>/Sirio/bin/sirioctl` (`bin-debug` for a debug build; `cli_install`), a copy and never a symlink, kept current by content. The PATH link (`cli_path`) is `~/.local/bin/sirioctl` on Linux; on macOS it is `/usr/local/bin/sirioctl` when the user can write there, else `~/.local/bin` when the login PATH searches it, and the administrator's password is asked only by the Settings button, never at startup; on Windows the stable directory joins the user's HKCU `Path`, which the Inno uninstaller removes. A file Sirio did not make at a link's place is never replaced, and the card names it. The socket can be disabled in Settings (`controlSocket.enabled` / `SIRIO_SOCKET_ENABLE`), which also disables Layer-A hooks.
